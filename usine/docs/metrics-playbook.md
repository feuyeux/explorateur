## 2. 抖音

### 2.1 逐条数据（播放 / 完播 / 跳出）

```
open_tab  https://creator.douyin.com/creator-micro/content/manage
wait      6s（首屏会先白屏，query kind=text 会只读到导航栏）
query     kind=text, maxChars 3000+
```

列表从新到旧，每支卡片带这些字段：

```
00:47  <标题> <正文全文>  编辑作品 设置权限 作品置顶 删除作品
2026-10-06 00:55  已发布
播放 12  点赞 0  评论 0  分享 0  收藏 0
完播率 0%  2秒跳出率 50%  吸粉量 0
```

- **审核状态**在这一行：`已发布` / `审核中`（`审核中` 时所有统计是 `-`）。
- `吸粉量` 是单条涨粉，比总数更灵敏。
- 卡片区不能用滚轮往下翻（坑 ③），一次读 3000+ 字符能覆盖最近 6–7 支。

### 2.2 账号级数据（总粉丝 / 平均播放时长）

**深链会白屏**（坑 ①）。正确路径：

```
open_tab  https://creator.douyin.com/creator-micro/home
wait      8s          # 首页自己会跳到 data-center/operation
query     kind=text
```

实际落在 `https://creator.douyin.com/creator-micro/data-center/operation`。读到的字段：

```
数据总览  统计周期 2026-09-29 至 2026-10-05（每日 12 点更新）
  播放量 1,817        超过 87% 同类作者
  互动率 1.3%         超过 63% 同类作者
  完播率 0.8%         低于 99% 同类作者     ← 关键
  作品数 23           超过 99% 同类作者
  粉丝净增 4          超过 61% 同类作者
播放量贡献 TOP3（每支的 7 日新增播放量）

作品数据  统计周期同上（每日 10 点更新前一日）
  投稿量 22  总播放量 2,073  总点赞量 13  总分享量 0  总评论量 9
  5秒完播率 20.65%   2秒跳出率 59.4%   封面点击率 35%   平均播放时长 4.72s

粉丝数据
  总粉丝量 3   粉丝净增 3   吸粉量 4   脱粉量 1   回访粉丝量 1
```

### 2.3 抖音判读基准

- **抖音自带百分位对照**（`超过/低于 XX% 同类作者`），**优先看平台自己的排位**，
  不要自己拍脑袋定好坏。
- **抖音是纯推荐分发**：**没有长尾**。单条前 2 小时定生死，24 小时定型。合集权重远低于小红书。

> **⚑ 小样本下不要用完播率 / 跳出率判单条好坏。**
> colors 14 语种实测（7–331 播放量级）里，完播率与播放量**几乎不相关**：
> 汉语 7 播放、完播率 10.0%（全场最高），阿拉伯语 331 播放、完播率 0.29%（全场最低）；
> 2 秒跳出率同样如此（阿拉伯语 63.8% 比死区的意大利语 63.3% 还高）。
> 这个量级下这些比率是噪声，**只在积累到数千播放的单条上才有意义**。
>
> **小样本期唯一的可靠信号是播放量本身**，以及账号级的百分位排位。
> 「平均播放时长」在账号级可用（基线 4.72s），但别下沉到单条。

## 3. 小红书

### 3.1 逐条数据

```
open_tab  https://creator.xiaohongshu.com/new/note-manager
```

每张卡片：`时长  标题  发布时刻  观看  赞  藏  评论  分享`。
滚动同样不可用（坑 ⑥），要用搜索框逐课程过滤（见 publish-playbook.md §8）。

### 3.2 账号级数据

**`/new/data-center/*` 全部 404**（坑 ②）。必须从笔记管理页点左导航：

```
open_tab  https://creator.xiaohongshu.com/new/note-manager
query     kind=semantic text=数据看板      → click
query     kind=semantic text=账号概览      → click
query     kind=text
```

落到 `https://creator.xiaohongshu.com/statistics/account/v2`。左导航还有
**内容分析** / **粉丝数据** 两个子页（本轮没取，需要时点进去）。

读到的字段：

```
账号诊断  统计周期 09-29 至 10-05
  观看数 3965（超过 98% 同类）  涨粉数 35（超过 99% 同类）
  主页访客 77（超过 95%）      发布数 44（超过 99%）  互动数 144（超过 97%）

数据总览
  曝光数 1.3万（环比 +4249%）
  观看数 3965（环比 +12290%）
  封面点击率 4%（环比 -62%）      ← 关键
  平均观看时长 17 秒（环比 -7%）
  观看总时长 9.2 小时（环比 +5355%）
  视频完播率 2.3%
```

### 3.3 小红书判读基准

- **小红书是长尾分发**：搜索 + 话题页 + 合集 + 主页互相导流。单条爆不爆不影响整体涨粉。
- **封面点击率**是这里的关键指标（对比抖音的 35%，小红书 4% 属于正常量级，两个平台的
  封面点击率**不可横向比**——抖音是信息流自动播放，小红书是主动点搜索结果）。
- 涨粉数比观看数更值得盯。观看涨了但涨粉没涨 = 内容被当工具查，没被当人关注。

## 4. 基线（2026-10-06 09:20 取，发布后约 8.5 小时）

### 抖音（周期 09-29 → 10-05，**不含** 10-06 凌晨发的 10 支）

| 指标 | 值 | 平台排位 |
|---|---|---|
| 总粉丝量 | **3** | — |
| 粉丝净增 | 3 | 超过 61% |
| 播放量 | 1,817 | 超过 87% |
| 完播率 | **0.8%** | **低于 99%** |
| 5 秒完播率 | 20.65% | — |
| 2 秒跳出率 | 59.4% | — |
| **平均播放时长** | **4.72s** | — |

本轮 10 支逐条播放：0 / 0 / 1 / 0 / 0 / 2 …（gift-poison、love-words、halb-uhr、indigo-road、count-cap、ja-nein-doch）
**但账号内 10-01 发的 01:17「第一幕全集」有 594 播放** → 账号没被限流，是这批内容没跑出来。

### 小红书（周期 09-29 → 10-05，含 10-05 22:52 起的 50 支）

| 指标 | 值 | 平台排位 |
|---|---|---|
| 观看数 | 3,965 | 超过 98% |
| **涨粉数** | **35** | 超过 99% |
| 主页访客 | 77 | 超过 95% |
| 曝光数 | 1.3 万 | 环比 +4249% |
| 封面点击率 | 4% | 环比 **-62%** |
| 平均观看时长 | 17 秒 | 环比 -7% |
| 视频完播率 | 2.3% | — |

### 结论（当时判定 · 2026-10-06 09:20）

同一批片子，小红书 8.5 小时涨 35 粉、抖音涨 3 粉。
当时判定主因是**抖音平均播放时长 4.72s**，流量在推荐第一层就被掐断；
次因判为「00:49–00:56 八分钟内连发 10 条 + 凌晨发布」。

> **⚑ 上面的次因判定已被推翻**（2026-10-06 晚）：colors 课 9 分钟内发 5 支，
> 拿到 61 / 253 / 331 / 49 / 147 播放。批量发布与发布时段都不是主因。
> 真正区分开的是**语种与包装**——colors 14 语种里 8 个播放 <50。
> 完整复盘在旧项目 strategy-2026q4.md（未随仓库迁移）；结论已并入本节上方。

小红书量在涨但效率在掉（封面点击率环比 -62%、观看时长环比 -7%），封面与标题需要加强。

## 5. 取数时的三个坑

### 坑 ① 抖音数据中心不能深链

`https://creator.douyin.com/creator-micro/data-center/home` 直接 `open_tab` 会**白屏**，
`query kind=text` 只读得到 7 个导航词。`data-center/operation` 同样如此。

**必须**先打开 `creator-micro/home`，等 8 秒，页面自己会跳到 operation 并渲染出来。

### 坑 ② 小红书数据看板全部 404

`/new/data-center/home`、`/new/data-center/overview` 都是「你访问的页面不见了」。
**必须**从 `note-manager` 点左导航「数据看板」→「账号概览」。

### 坑 ③ 两边列表的滚动容器都不响应滚轮

抖音 `content/manage`、小红书 `note-manager` 的 `scroll` 都返回
`moved: false, actualDeltaY: 0, atEnd: true`。

- 抖音：`query kind=text` 一次读 3000+ 字符，覆盖最近 6–7 支；要更多只能靠搜索框。
- 小红书：用顶部搜索框逐课程过滤，每门返回「共 N 篇笔记」（注意搜索是**分词模糊**的，
  搜「6个身体词」会混进「6个天气词｜03日语」，**按标题判定而不是只看计数**）。

## 6. 什么时候该取数

- 发完一批的 **24 小时后**看一次（抖音已定型）。
- 打算改内容形态前看一次（账号级平均播放时长 / 平台百分位排位决定要不要改）。
- 两平台对比涨粉时以**同一统计周期**为准——两边周期标签不一样
  （抖音「每日 12 点更新」，小红书「每日 10 点更新前一日数据」），差一天会误判。
