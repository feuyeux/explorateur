# 发布踩坑与经验教训总账

> 本文档记录的是**实际踩过**的坑，不是理论。每条都注明平台、现象、根因、修法。
> 新增坑请追加到对应平台小节，并在 `AGENTS.md` 加一行速查。

## 0. 跨平台通用

### 0.1 证据源优先级：截图 / 像素 > 脚本自报

脚本自报成功**不构成证据**。反复出现「脚本说找不到、截图里明明有」和
「脚本说成功了、截图里根本没生效」。

- 只有**作品管理页缩略图里能看见文字**才算封面生效。
- 只有**重新打开编辑页看到字段值**才算字段落库。
- 只有**打开面板看到「已添加 / 共 N 个作品」**才算入集。

抖音合集那次，脚本连报两次假警报（说「缺英语版」「还有 12 条可添加」），
实际截图是完整的 01–12；反向也发生过——脚本说「视频数没增」是真失败。
**一律去看截图**。

### 0.2 未知状态一律当失败

「无法确认是否成功」= 失败。不许静默 fallback 到默认值，不许当通过。
本项目因此删掉了三个平台发布脚本里所有「封面上传失败 → 用默认首帧 → 继续发布」的兜底。

### 0.3 每条任务开始前强制重置页面

跨条脏状态污染比单条失败危害大得多。跨条污染的真实案例：
小红书 03 撞风控扫码后，残留的 `d-modal-mask` + WebGL canvas 没消失，
导致 04–12 全部把上一条（德语）的封面重复盖上去，
直到第 5 条才发现编辑器里躺的还是第 3 条的封面。

### 0.4 撞风控绝不自动重试

风控（小红书「Scan to verify」）必须停下来让用户本人扫码，浏览器窗口保持打开。
自动重试只会越撞越死。解除后**必须确认遮罩真的消失**，不能只看文案。

### 0.5 日志必须 `python3 -u`

不加 `-u` 时 `tee` 出来的日志文件是空的，会让人误以为脚本没跑。

### 0.6 长会话会被 Playwright 打断

Playwright sync API 在同一个会话里跑久了（尤其多轮视频上传 + 大段 DOM 操作）会出现：

```
Error: Event loop is closed! Is Playwright already stopped?
```

此时 `page.is_closed()` 仍然返回 `False`，但**所有 `evaluate` 全挂**——极具迷惑性。

**修法**：长任务拆成短命进程，每批干完就退出，靠磁盘上的进度 JSON 接力。
旧知乎项目用 `zhihu_relay.py` 的 `--all` 模式落实过这个形态（内容项目侧脚本，不在 feuille）。

### 0.7 正文变长后，纯文本定位器会点错

正文里也可能有独立成段的「视频」二字（知乎长文里就有），
此时 `get_by_text("视频").first` 会点到正文而不是工具栏按钮。

**修法**：永远用结构化定位，不要用纯文本。
```python
page.locator("button[class*='ToolbarButton']")   # 锁定工具栏
```
这条坑在知乎正文从 2000 字涨到 5330 字后突然出现——**正文变短时测试通过的脚本，长的必然坏**。

## 1. 抖音

### 1.1 合集批量加作品：`target[0]` 陷阱

`JS_ROWS` 去重后每轮都 `return target[0]`，12 次点击全打在**同一行**（希伯来语），
结果「合集内作品 1」。

**修法**：别去推算「下一行该点哪」，直接定位「+」按钮本身——
面板里未添加的行右侧是 24×24 的 svg，已添加的行文字含「已添加」，据此排除。

```python
if (r.width - 24) > 3 return;  if (r.x < 1500) return;
if (row.innerText.includes('已添加')) return;
```

### 1.2 作品面板会被服务端错误清空

批量加点过程中弹 5 个「服务器/网络开小差了」，作品列表变成「共 0 个作品」，
`JS_ROWS` 返回空 → 脚本以为「没有未添加的行了」而放弃。

**修法**：空列表 ≠ 做完。要**重搜自愈**，最多重试若干次。
同时脚本在数量 ≠ 目标时**拒绝点保存**，这一条救了整批（它自己拦下来的）。

### 1.3 封面必须发完视频后单独补

上传流程的封面面板喂不准（`file input[0]` 挂在「生成参考图」下）。
正确做法：先发 12 条视频，再用 `fix_all_douyin_covers.py` 补封面，
最后 `verify_douyin_covers_live.py` 只读回查。抖音每个作品**最多改 5 次**。

## 2. B站

### 2.1 合集功能有等级门槛（Lv2），UI 上无解

编辑页「加入合集」是纯灰字说明，**没有任何可点控件**，提示需创作中心等级达 Lv2。
合集管理没有独立页面（`/platform/upload-manager/collection(s)`、`/series/manage` 全部 404 或重定向）。

**这是账号等级门槛，无法绕过。** 要做只能先提升等级。

### 2.2 封面必须兼容 4:3 居中裁切

卡片展示区压到中央约 72%，上下会裁。封面文字必须落在安全区内。

### 2.3 提交按钮不是 `<button>`

成功文案是「**稿件投递成功**」不是「提交成功」。
投稿页每条**强制刷新**，否则表单残留触发「批量上传」遮罩拦死表单。
下拉选项有进场动画，得用 `page.mouse.click`；选中后 `input.value` 不回写，不能靠它判断。
「内容为自制」在**非必选**版权声明区，填不满必填创作声明。

## 3. 小红书

### 3.1 「发布」键只能用像素定位

连破 5 轮：文案查找 → 页签 → hover 按钮 → 要求 `<button>` → `elementsFromPoint`，
**全部落空**。它不在主文档可命中区域（很可能是跨源 iframe / 合成层），
但 Playwright 截图能合成出来。

**修法**：截图喂回浏览器 → canvas `getImageData` → 扫底栏品牌红 `#FF2442`。
实测命中 119×39 的红色药丸、4233 个红像素。

### 3.2 笔记管理是真长列表 + 懒加载

滚动容器不是 window，要用 `page.mouse.wheel` 且鼠标要移到列表区域。
首屏只渲染一部分卡片——实测要等 14 次轮询才凑齐 12 条。
加搜索过滤 + 提前中断会漏采，曾误报 11 条。

### 3.3 「编辑」不是文字按钮

卡片 hover 才显形，是 `.note-card__actions` 里第 4 个 20×20 的图标
（tooltip 是「编辑」）。顺序：合作人 / 置顶 / 数据统计 / **编辑** / 删除。

### 3.4 封面编辑器里有两个 AI 入口

「✨生成封面」「✨获取封面建议」一律不碰，「PK封面」开关保持关。
画布是 3:4，把 9:16 封面按已审计安全区**预裁成 1080×1440** 后零裁切。

### 3.5 两个对外声明字段保持默认留空

「原创声明」「添加内容类型声明」不替用户勾任何对外声明（与 B站「内容无需标注」一致）。

## 4. 知乎

### 4.1 ⚠️ 一篇文章最多只能发 10 个视频

**本项目实测确认**：12 支视频插到第 10 支时，日语、韩语两支始终无法完成上传
（选完文件 7 秒后弹窗消失，`figure .Editable-video` 数量不变）。
最终按用户决定：**保留 10 支视频，日语/韩语章节只留文字**。

下次做多视频长文，**先按 10 支封顶设计**，不要指望能插满 12 支。

### 4.1b ⚠️⚠️ 知乎对阿拉伯语不友好 —— 发该语种有违规风险

**用户明确告知的平台特性，务必在选题阶段就考虑，不要事后再补救。**

知乎作为中文平台，涉及**阿拉伯语 / 伊斯兰语境**的内容审核明显偏严，
同样内容在小红书、抖音、B站能过，在知乎可能被拦下、限流或要求修改。
原因是这类内容天然靠近「宗教传播」这条红线。

本项目的具体暴露点（发布前应逐条确认）：

| 位置 | 内容 | 风险判断 |
|------|------|----------|
| 第 8 章 阿拉伯语 | 大量带 harakat 元音符号的诗句（`نَزَلَ` `وَهَبَّتِ`） | **高** —— 密集阿拉伯文排版本身容易被机器判为宗教文本 |
| 第 8 章 正文 | 提到 `بحر الكامل` / `بحر الرجز` 两个古典诗律名 | **中** —— 属文学术语，但仍是伊斯兰学术语 |
| 第 9 章 希伯来语 | 直接引用《诗篇》Psalms、《约伯记》Job，并写「来自《诗篇》与《约伯记》的语汇」 | **中** —— 圣经引用，中文平台对基督教/犹太教经文的容忍度高于伊斯兰，但仍有风险 |
| 第 9 章 希伯来语 | 「一旦脱离《圣经》土壤就几乎无法运作」 | **低** —— 文学性表述 |
| 结尾 | 「希伯来语：诗篇（Psalms）中的同义对句结构」 | **低** |

**处置建议（下次发之前先做）**：

1. **要么**把阿拉伯语章节从知乎版里整章移除，只在其余 11 个平台发；
2. **要么**保留章节但去掉所有 `بحر` 诗律名与 harakat 密集排版（只留裸字母）；
3. **要么**接受被拦的风险，发之前先确认账号当前是否已收到过知乎的违规提醒。

**不要**默认「其他平台能过知乎也能过」。跨平台一致性原则在**合规**维度上要让步于
各平台自己的审核尺度——`AGENTS.md` 里「四平台一致性」指的是封面/标题/正文齐备，
不是指**争议内容必须四平台同步**。

### 4.2 Markdown「导入」功能不可靠

底部有「导入」按钮、file input 也接受 `.md`，但：
选完文件后弹窗要**先勾选右侧圆圈**（「默认储存在我的直答知识库」）才激活按钮；
本次勾选框定位失败，结果**把 `zhihu-import.md` 这个文件名当正文插进去了**。

**修法**：别用导入。改成解析 Markdown → 分段 `keyboard.insert_text` 填正文 →
按块类型点工具栏（`##` → 「标题 ▾ → 二级标题」，`>` → 「引用」，`---` → 「分割线」）。

### 4.3 「Markdown 语法输入中」是不可切换的提示文字

底部那行字看着像模式开关，点了没反应，页面只有 1 个 `contenteditable`。
**别指望能切到 Markdown 模式直接贴。**

### 4.4 所有「选择文件」弹窗都要先勾圆圈

文章封面、「导入文档」两个弹窗机制一样：选完文件后底部按钮仍是灰的
「请选择文件」，必须先点文件条目右侧的圆圈
（`div` 约 20×20，class 形如 `css-175oi2r r-1loqt21`）才激活。

不点它 → 弹窗一直挡着 → **底栏「发布」点不到**。
本次封面上传就是这么失败的：点圆圈没生效，弹窗挡住发布键，
最后文章是**带着文件占位卡片**发出去的。

### 4.5 视频标题：`insert_text` + `Escape` 填不进去

视频卡片标题控件是 `div.Editable-VideoTitleInput-value`（占位符文案
「好的标题可以获得更多的推荐及关注者」）。

- `insert_text` 后按 `Escape` → 内容被撤销，`data-name` 永远是空串
- **正确**：`click` → `keyboard.type(delay=15)` → **点标题框失焦**（不要 Escape）

### 4.6 视频自动取首帧作封面 —— 正好是我们要的

上传后知乎自动抓视频首帧做卡片封面。因为我们的视频第一帧就是**带文字的预制封面**，
所以**零额外操作就满足封面铁律**，不需要单独传视频封面。

### 4.7 草稿自动保存是唯一的救命稻草

知乎每 N 秒自动存草稿（底部显示「刚刚 · 草稿」），这让「跑一半被打断」不致命：
从 `https://www.zhihu.com/creator/manage/creation/draft?type=article`
找到草稿，进 `/edit`，按「最后一支视频对应第几个语种章节」反查续跑点即可。

本次正文就是这样接力 5 批写完的。

### 4.8 发布后文章 URL 会暂时重定向到首页

发布成功后 URL 变成 `https://zhuanlan.zhihu.com/p/<id>`，
但**立刻访问这个 URL（含 `/edit`）会被重定向到首页推荐流**，
创作中心内容管理列表里也还看不到。推测是审核期内作者侧也未开放访问。

**不要**因为「打不开」就判定发布失败——以「发布后 URL 从 `/edit` 变成 `/p/<id>`」为准。

## 5. 环境与工具

| 事项 | 结论 |
|------|------|
| Playwright 脚本 | `uv run`（`uv sync --group publish` 后） |
| 其余 Python | `uv run python` |
| 日志 | 必须 `python3 -u`，否则 tee 出空文件 |
| 临时脚本 | 放项目目录，**不要**放 `/tmp`（`/tmp/inspect.py` 会遮蔽标准库 `inspect`） |
| 文字渲染 | 走 HTML + Edge headless 截图，**不用 Pillow 画字**（本机 `raqm=False`，阿/希/天城文会散字） |
| 图片拼接 | `magick montage` 缺字体，用 `-append` |
| 进程清理 | `pkill -9 -f "<profile 名>"`。**不要**用 `pkill -f "zhihu"` 这种宽泛模式——它会把自己启动的脚本也匹配上 |
| 删除 | `/Users/han/.minimax/bin/mavis-trash --` |

## 6. 发布前自检清单

1. 封面是**预制带文字图**，不是平台默认首帧
2. 封面文字落在该平台的**真实裁切框**安全区内
3. 分区 / 创作声明这类**有实际责任**的字段已由用户拍板，没替用户勾
4. 发布后**重新打开管理页/编辑页截图核对**，不看脚本自报
5. 数量对不上就**拒绝提交**，不做静默降级
6. 撞风控就停下等用户，不自动重试
