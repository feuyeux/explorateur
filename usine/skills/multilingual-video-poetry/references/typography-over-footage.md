# 实拍画面上的多语种排版

## 为什么必须走 Edge headless

| 方案 | 问题 |
|---|---|
| ffmpeg `subtitles`/`ass` 滤镜 | 常见构建未编 libass，滤镜直接不存在 |
| Pillow 画文字 | `raqm=False` 无 HarfBuzz/FriBiDi，阿拉伯／希伯来／天城文散字错向 |
| **Edge headless** | Chromium 内核自带完整塑形，一次截图就对 ✅ |

用 `src/feuille/textlayer`：

- `shoot_matte(html_fn, out, ...)` — 透明叠加层。白底/黑底双截 → 精确 alpha
- `edge_screenshot(html, out, ...)` — 不透明整图（封面等）。自带视口亏空补偿与裁齐

### 铁律：截图必须串行

并发 Edge 截图会被 SIGKILL，炸掉是**整批重做**。96 张卡片串行约 20 分钟。

## 字体

**字体栈一律从 `languages/<locale>/manifest.json` 取，不在脚本里另抄。**
`data.py` 是按键取值，所以给注册表**加**键是安全的。

需要更有艺术感时，加一个展示字体键而不是在脚本里硬编码：

```json
{
  "fontCss": "...原样保留...",
  "displayFontCss": "'Baskerville', 'Palatino', 'Charter', 'Georgia', <原 fontCss>, serif"
}
```

**末尾必须接回原 `fontCss` 兜底**——缺字或字体缺失时行为与从前完全一致。
`data.py` 按键取值，其他项目不受影响。

各语种按其**实际书体传统**选，不是一个 Latin 衬线了事：

| 语种 | 展示字体 |
|---|---|
| 拉丁／希腊／西里尔 | Baskerville · Palatino · Charter |
| 中文 | 宋体 Songti SC / STSong |
| 日文 | 冬青明朝 Hiragino Mincho ProN |
| 阿拉伯 | Al Bayan · Baghdad（纳斯akh 体） |
| 希伯来 | New Peninim MT |
| 天城文 | Devanagari Sangam MN |

**注册表里全是无衬线**是「排版硬邦邦」的常见根因——先查这里再改 CSS。

## 阴影：文字压在实拍画面上

亮天空与白雪会吃掉单层柔和阴影。用**三层叠加**：

```css
text-shadow:0 2px 3px rgba(0,0,0,.45),      /* 近距实边：定字形边缘 */
            0 3px 22px rgba(0,0,0,.55),     /* 中距晕开：托住主体 */
            0 10px 50px rgba(0,0,0,.4);     /* 远距散光：融进画面 */
```

## 配色：**不能靠色**

配色是看着挑的就会漏。眼睛会被色相骗，对比度是量得出来的。

实测教训：冬季冰蓝初版 `#69B4E8` 叠在白雪上几乎看不见——因为「冷色配雪」
在直觉上完全成立。压深两档才对。

### 先量背景亮度，再决定往哪个方向调

```bash
uv run python skills/multilingual-video-poetry/scripts/color_contrast.py \
    --seasons 母版.mp4 --cards cards/横版
```

它输出每个季节文字区的**紧邻背景亮度**，并指出哪一季的底色量级最高。
本项目的实测结果：

| 季 | 环带 p50 | 环带 p90 |
|---|---|---|
| 春 | 0.103 | 0.168 |
| 夏 | 0.135 | 0.236 |
| 秋 | 0.110 | 0.328 |
| **冬** | **0.486** | **0.601** |

**冬季背景亮度是其余三季的 3.6 倍。** 这才是冬季要连压两档的**可测原因**——
不是「颜色没选好」，是底色根本不在一个量级。目视只能看出「看不见」，
量能量出「差多少倍」，从而知道该重点盯哪一季、该往哪个方向调。

### ⚠️ WCAG 对比度**不适用**于彩字压实拍

`color_contrast.py` 会顺带算 WCAG 亮度比，但**不要拿它判定合格**。
实测四季全部「不达标」（1.36–2.78），而这些成片是逐帧目视验收过、可读的。原因：

- WCAG 为 **UI 文字压平底色**设计，那里没有阴影光晕、没有纯色相区分；
- 彩字在实拍上靠**亮度差 + 色相差 + 阴影光晕**三者叠加，WCAG 只看第一项，
  会系统性低估彩字的可读性。

所以脚本**不以 WCAG 判定退出码**。真正的验收是**目视复核渲染后的合成帧**——
但**先量背景亮度**，才知道该盯哪一季。

### 字形掩膜的参数是标定出来的

工具里字形掩膜用「色相容差 0.03 + 亮度 > 0.5」。不是拍的：

- 容差 0.09 会把夏天的天空与草地一并抓进来（占区域 **68.5%**），量出来全是噪声；
- 0.03 + v>0.5 才精准命中字芯——此时字形亮度 p75 与该色实算亮度一致
  （实测 0.635 vs 0.636），可以自证。

**掩膜本身也要验证**，别默认它抓对了。

### 背景取「紧邻环带」而不是整条画面带

远处的高光区与文字的可读性无关。先膨胀字形掩膜取环带，再在环带里取 p90
（亮字最易被吃掉的地方）。

### 挑色时仍然要目视复核

量完背景亮度是**缩小排查范围**，不是免掉目视。冬季就是量出 3.6 倍之后，
对着合成帧复核才发现要压两档。

## 绝对定位 vs 流式

逐元素绝对定位时，**1 行标题和 2 行标题的间距会不一致**——第二行会顶到上面的元素。
季名／细线／标题这类块级元素应放在一个**底部锚定的容器**里自然向上生长：

```css
.block{position:absolute;left:76px;right:76px;bottom:118px}
```

## 封面

- 尺寸 **1080×1440（3:4）**，平台推荐比例
- 抽帧用**无字幕母版**（`*_20s.mp4`），不要用已烧字幕的成片——否则一屏挤两层字
- 取帧跟着**文案的主题季**走，图和文要对得上
- 标题 ≤ 20 字，超出会被截断。批量产出后**务必机器校验字数**，初稿有 5 条超限
- 封面标题从文案 md 里读，不另抄一份——改文案标题封面跟着变
