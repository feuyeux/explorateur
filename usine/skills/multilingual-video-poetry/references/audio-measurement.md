# 音频测量方法

**量不出来就不要改。** 本项目里所有「声称」都必须有对应测量；量不出来就撤下声称
（AGENTS.md 纪律 22）。同样，量出「有问题」也要先确认测量本身没错——
见文末「一次差点改错的测量」。

## 核心方法：拆轨对比

只听最终混音定位不了问题。把滤镜图拆成独立分轨逐段对齐：

```
人声干轨  vs  被压 BGM 轨  vs  最终混音
```

三条轨同源同长，同一时间点横向对比，一眼看出是哪一环丢的。
`scripts/audio_profile.py` 实现了这个。

## 分段电平：两种工具，别混用

### `volumedetect` — 测单段，可靠

```bash
ffmpeg -ss 6.1 -t 0.3 -i mix.wav -af volumedetect -f null - 2>&1 | grep mean_volume
```

⚠️ **不要加 `-v error`**，volumedetect 的输出在 info 级，会被吞掉，拿到空值。

### `astats` — 扫全曲线，分辨率高但需小心

```bash
ffmpeg -i mix.wav -af astats=metadata=1:reset=5,ametadata=print:key=lavfi.astats.Overall.RMS_level -f null -
```

`reset=5` 是每 5 帧（48kHz 下约 100ms）重置一次。适合画电平曲线看**趋势**，
但逐点数值与 `volumedetect` 不完全一致——**下结论前用 `volumedetect` 复核**。

### 感知响度（LUFS）— 比 RMS 更接近听感

裸 RMS 会误导：同样 −20 dB RMS，密集音乐和语音的听感响度完全不同。

```bash
ffmpeg -ss 0.55 -t 2.2 -i mix.wav -af loudnorm=I=-16:print_format=json -f null - 2>&1 | grep input_i
```

定稿判据示例：人声段 −15.3 LUFS，底床 −23.4 LUFS，人声高出底床 8.2 dB。

## 侧链压低量的正确测法

想量「BGM 被压低多少 dB」，**不能拿压前压后两条比**——曲子自身的力度起伏会混进来。

正确做法：从**同一条被压轨**上取「人声段」与「空档段」对比，起伏被抵消。

```
被压 BGM 轨 · 人声段  −32.4 dB
被压 BGM 轨 · 空档段  −25.8 dB
                          → 压低 6.6 dB
```

## 空档窗口的定义

空档 = **上一段旁白结束 → 下一段旁白开始**。写成 `上一段结束 → 下一段结束` 就错了。

## 一次差点改错的测量

曾用「上一段旁白结束 → 再下一段**结束**」当空档，测出底床 −18 LUFS、人声 −15 LUFS，
只剩 3 dB 差距，差点去调电平配比。

实际上那个「空档」窗口**压进了下一段的旁白**，读数虚高。修正窗口定义后测得底床
−23.4 LUFS、配比本来就正确——**那个 bug 根本不存在**。

教训：量出异常结论时，先确认**测量窗口的定义**对不对，再去改被测对象。

## 已被证伪的启发式，不要再用

**用频谱目视判断有没有人声**——第一轮 BGM 被判定「无明显人声共振峰结构」，
用户听后直接反馈仍有人声。该启发式不可靠，不要重复使用。

有无人声只能由人耳判定。要么让用户试听，要么用**构造上不可能含人声**的音源。
