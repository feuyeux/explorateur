# 比分牌映射的实测坑表

全部数字来自 2026-10-25 米兰德比实跑（485.48s 意甲官方 extended highlights，比赛 95 分钟；项目产物按落位规则在 `usine/examples/` 下、不入库，可能已清理——数字已固化在本文件，不依赖那个目录还在）。换比赛 / 换联赛时**方法照抄、数字重测**。

## 1. 映射表怎么建

- 全片 `fps=1` 采样（485s 母版 = 485 帧 png）；
- 转播比分牌位置整场固定，裁出时钟/比分区竖拼成长图逐帧读 MM:SS 与比分。
  derby 实测裁窗：`crop=100:36:170:86`（时钟列）与 `crop=60:36:400:86`
  （比分列）。**先抽 3–5 帧探针定裁窗再批量裁**——每个联赛转播包的比分牌
  几何不同，抄别的联赛的坐标必裁空；探针脚本 `probe_scoreboard.py` 会给
  候选裁窗 + 竖拼长图（`--stitch N` 覆盖探测窗口的**前 N 秒**，不是全片）；
- ffmpeg 场景检测 `select='gt(scene,0.25)'` 的切点聚集与比分牌读数互相印证；
- **探针有地板**：所有候选带的变化密度都低于 0.25 次/s → `found: false`、
  退出码 1——这条母版里没有比分牌，没有映射基准，本 skill 对它不适用。

## 2. 集锦的时间轴不是匀速的

95 分钟压进 485s，名义压缩比 ≈ 11.7×，**逐段 10×–20× 还不等**——回放段
压缩比是负的（时间倒流），庆祝段几乎原速。任何「按比例换算比赛分钟 → 视频
秒」的写法都错，窗口落点只能来自比分牌读数 + 场景切点。

## 3. 跳切：被跳过的事件放在跳切上讲

官方集锦会整段跳时间。derby 实测两刀：

- 视频 311→314s：比赛时钟 69:46 → 73:26；
- 视频 353→354s：比赛时钟 74:56 → 89:58。

72 分钟国米换人、81–89 分钟双方换人都发生在被跳过的时间里——**画面里根本
没有换人镜头**。这两段换人解说就放在跳切点上，旁白说的时刻与画面跳掉的
时间一致；不要去找不存在的换人画面，也不要把解说落在跳切前（观众看到的
还是 69 分钟的画面，听到 72 分钟换人会错位）。

窗口表里这两段记 `kind: 'jump'`、`visible: 'absent'`：旁白只报进程与战术影响，用「这两分钟里」开头，不写任何动作细节（换人镜头不存在）。写法见 [visual-commentary.md](visual-commentary.md) §4.2。

## 4. 进球包是三段结构

一个进球在集锦里通常 = 现场画面 → 比分牌动画 → 慢放回放，三段各占一个窗口。
derby 第 4 分钟进球实测：现场 36–42s、比分动画 ~42s、回放 43–57s。写词时
分开处理：现场段讲过程，回放段讲细节（跑位 / 脚法），不要两段说同一句话。
场景检测里进球包表现为 0.5+ 的切分聚集（42.68 / 56.32 两处 score 0.53–0.62）。

三段在窗口表里各占一个窗（`kind` 分别 `live` / `graphic` / `replay`），信息职责分开：现场讲过程、比分动画讲数据与意义、回放讲细节。一窗里既现场又回放，旁白必然有一半对不上画面。

## 5. VAR 图形页是可读锚点

VAR 段有整屏图形页（derby 336–345s，页面写 PAVLOVIC / FOUL）——把页面上
**实际出现的名字与判罚词**当锚点写进事实，不要从旁白或比分倒推是谁的手球。
改判结果（点球 → 角球）以官方比赛页事件表为准。

## 6. 终场哨的判定

终场哨 = 场景切点聚集 + 比分牌最后一次可读（derby：403–406s，最后读数
95:03）。之后的画面是握手 / 绕场 / 看台，写「赛后」窗口。片尾如果整段变黑
或出字幕，场景分会出现 1.000000（derby 472.44 / 475.44 两帧）——那是片尾
不是事件，别把它当终场哨。

## 7. 换了工作区/母版，旧映射一律作废

比分牌几何、压缩比、跳切位置都是**这一条母版**的属性。凡是换过母版、
换过裁窗，旧映射表不许复用，重走第 1 节。探针脚本（候选裁窗 + 竖拼长图
逐帧存档）是 `scripts/probe_scoreboard.py`，方法可复跑，数字不搬。

## 8. 渲染中断的 mp4 不是产物

成片渲染十几分钟，被杀（会话结束 / 断电 / 手动停）就留下没有 moov atom 的
文件——`ffprobe` 报 `Invalid data found`，**不管文件看起来多大**（derby
实测 288 MB 的废片）。判定口径只有 ffprobe 能过；重跑前先删废片。
教训：成片渲染跑后台，跑完第一件事 `ffprobe` 验时长，再谈别的验收。

## 9. 没有视觉输入：用 OCR 读数（2026-11-02 实跑）

实跑「拜仁 2-2 多特」时，运行环境没有图像输入（模型不能看图，视觉代理供应商
不可用）。读数改用本地 OCR：

```bash
python3 scripts/probe_scoreboard.py master.mp4 --out probe.json
python3 scripts/read_scoreboard.py master.mp4 --from-probe probe.json --out sb.json
# 或手动指定裁窗（w:h:x:y）
python3 scripts/read_scoreboard.py master.mp4 --crop 480:110:1440:0 --out sb.json
```

`read_scoreboard.py` 输出逐帧 `minute / score / texts`、`score_changes`
（进球锚点）与 `jumps`（跳切候选）。两种时钟形态都认：`60'`（分钟）与
`89:58`（MM:SS）——MM:SS 按时钟读（第 89 分钟），不会误读成比分 89-58。
**读数有下限（fail-closed）**：一帧分钟都没读出来 = 裁窗多半不对，退出码 1
并回显裁窗，不许拿全 None 的读数冒充「读过了」；分钟覆盖率 < 20% 给 stderr
警告。**OCR 会把 8/6 认混**：本场最后一段比分牌读成 `68'`，但比分 `2-2` 与
官方事件 89' 席尔瓦绝平一致，场景切点也在 153.48s——用「比分变化 + 官方事件
分钟 + 切点」三方互证，不能只信 OCR 的分钟。

### 德甲比分牌是「分钟」，不是 MM:SS

德甲转播的比分牌实测显示 `60'`（分钟）和 `FCB:BVB`、`1-1`，**没有秒**。
所以映射粒度就是 1 分钟，不能写出「第 60 分 37 秒」这种伪精度。意甲的
MM:SS 是意甲转播的属性，不是所有联赛的默认。

### 母版可能带采访：先裁集锦本体

BVB 官方 6:03 的 highlights 后 3 分钟是球员采访（描述里有「I'm glad I was
able to help」）。先看 `yt-dlp -J` 的 description 与比分牌最后一次读数，
把采访段裁掉：本场集锦本体 0–162s，采访 162–363s。**母版时长 = 集锦本体**，
不是视频文件时长；否则窗口表会排到采访画面上。

### 本场实测数字（换比赛时重测，不要抄）

- 比分牌裁窗 `crop=480:110:1440:0`（1920×1080；top-right）
- OCR 锚点：38'@52s、60'@96s、66'@126s、89'@155s

## 10. 四场实跑的比分牌格式（2026-11-02）

同一套 `probe_scoreboard.py` + `read_scoreboard.py`，四个联赛的实际格式并不一样：

| 联赛 | 裁窗（1920×1080） | 时钟格式 | 实测读数 |
|---|---|---|---|
| 德甲 | `480:110:1440:0` | **只有分钟** `60'` | 38'@52s、60'@96s、66'@126s、89'@155s |
| 西甲 | `900:130:0:70` | `MM:SS`（真实比赛时间） | 08:32@20s、23:00@45s、41:13@76s、64:00@120s、84:05@164s |
| 法甲 | `900:170:0:90` | `MM:SS` | 17:32@29s、27:41@100s、54:19@140s、61:19@180s、68:35@220s |
| 英超 | `900:130:0:5` | **只有比分**（`LIV 0-1 ARS`） | 0-0→0-1 在 t≈10s；无可用时钟 |

两条由此固化的规矩：

1. `read_scoreboard.py` 先认 `MM:SS`，再认 `60'`；`MM:SS` 与比分正则撞车时
   （`07:52` 会被读成 7-52）必须跳过同一段文本，否则「比分变化」会刷出上百条假变化。
2. 英超这类只给比分的比分牌，**进球锚点用比分变化**（0-0→0-1 在 t≈10s），
   其余事件靠官方分钟 + 场景切点；不要假装读到了时钟。
