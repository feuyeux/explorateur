# 交付前自检（绿灯不等于做对了）

这篇记录的是 2026-10-11 阿语偏正结构视频（`examples/arabic-idafa`）连续返工 4 轮的
根因。产线本身没坏——门禁全绿、同步 15/15、时长帧数精确——**但用户还是改了 4 次**。

改动都落在门禁管不到的地方：封面塌了、中文注解颜色错了、台词没删干净、"卡拉OK"
做成了台词条。这些失败一次性暴露了验收模型的一个缺口，所以这篇比任何一条 ffmpeg
陷阱都重要。ffmpeg 陷阱在 [av-sync.md](av-sync.md)。

---

## 1. 根因

### 1.1 「门禁全绿」被当成了「做对了」

上面 SKILL.md §Workflow 6 原文写着 *"the model cannot watch the video — the gate is
programmatic"*。**这句话是错的**，而且它直接授权了下面这个错误。

门禁能回答的只有一个问题：**成片和我渲染出来的状态帧一致吗？** 它回答不了：

| 用户反馈 | 门禁为什么全绿 |
|---|---|
| 封面塌成一个点 | `scan_blank` 只判"接近纯白"，塌掉的封面底色不是白的 |
| 中文注解颜色不对 | 没有任何检查问过"这个词该是什么颜色" |
| 台词没删干净 | 没有任何检查问过"这一镜该不该有这句话" |
| "卡拉OK"做成了台词条 | 高亮逻辑自洽，只是高亮的不是用户想要的东西 |

**每一条都发生在全绿之后。** 绿灯的准确含义永远是"我检查的那件事成立"。

### 1.2 模糊指令取了最小字面解释

用户说「台词不要放下面」。这句话有两层：① 下面那行逐词 token ② 整句台词。
我删了 ①，画面上 ② 还在，于是用户必须再说一遍「**不要把台词展示出来**」。

同一轮的「阿语播放时要卡拉OK」，我做成了"画面下方一条逐词点亮的句子"——正是用户
下一条骂的"**现在不是卡拉OK的模式 而是台词放下面了**"。

两次是同一个错误：**用最小改动交差，而不是先确定要动的是哪一层。**
"删掉某个东西"的指令几乎总是指向一个**层**（哪一层 UI / 哪个数据源），不是指向
某一个具体元素。

### 1.3 门禁只问"一致"，不问"正确"

阿语词表那道门禁是「拿词表校验源文件」——而词表自己把 ر 在 رصاص 一族里的
فَتْحَة 写成了 كَسْرَة。于是全库 18 处错误元音一路绿灯到出片，报告是漂亮的
「✓ 全部命中」。**我加的每一道门禁都在问"和我算出来的一样吗"，没有一道在问
"这样对吗"。**

### 1.4 显示工具骗人，而我反复信它

终端把 U+064F(كَسْرَة) 和 U+0650(ضَمَّة) 画得几乎一样，一天被骗 **5 次**，每次都
先怀疑数据。**任何需要区分相近字符的判断，必须有门禁明确禁止用眼睛做。**

## 2. 交付前自检清单

按顺序做。**第 1 步在任何 build 之前**，第 4 步不可省。

### 步骤 1 — 歧义先定，不取最小解释

- 指令里出现「不要 X」「改成 Y」「只留 Z」时，先问/先定**哪一层**。
- 两种读法会导致不同结果时，**做一个能区分两者的验证**（渲染两版抽帧对比），
  而不是赌一个。赌错一次的代价是用户多打一行字，你多跑一轮 build。
- 用户给了否定式反馈后，他下一句通常是**更精确的同义句**（"不要把台词展示出来"
  = "不要把台词展示出来"，不是"再删多一点"）。把他这句直接当需求实现。

### 步骤 2 — 门禁要有一条不查自己

任何 `check(输入) 对照 权威表` 的门禁，若那张表也是人手写的，表错了它只会把错的
判成对的。**至少留一条判据的真相不来自那张表**（把权威形式写成规则/常量，让它
反过来校验表）。详见 Agent Memory 同名条目。

### 步骤 3 — 逐 token 复数，不靠门禁没报错

批量改写源文件之后，**另数一遍 token 数 / 结构元素数**。各条门禁的失败模式不对称：
strict=True 的会报错，strict=False 的可能一个字都不吭——而"删掉一个字母"恰好
制造了"未登记"，于是被 strict=False 那条跳过了。

### 步骤 4 — 亲手打开产物看

**这一步不能省，也不能用门禁替代。**

```bash
# 每个有代表性的时刻抽一帧，然后【用 read 工具把图看进眼里】
ffmpeg -v error -y -ss <t> -i out.mp4 -frames:v 1 check/f_<name>.png
```

抽哪些时刻：

- **每一镜至少一帧**，不要只抽第一镜；
- **每一个"应该被点亮"的时刻**（token 生效的中段），确认高亮的确实是目标元素；
- **首帧 / 尾帧**（封面、收尾卡），塌缩类退化只在这里出现；
- **颜色编码出现的位置**——用户说"颜色不对"时，对照的是**它标注的那个外语词**，
  不是别的元素（见 §4.3）。

`<t>` 从 `feuille karaoke verify-sync` 的输出里取 `word0` 那一列，别自己估。

### 步骤 5 — 验收脚本跑完，再问一遍"它管的是不是这件事"

`scan_blank` 通过的含义是"没有接近纯白的帧"。它判不出内容缩成一个点。
**绿灯之后至少再人工打开一次产物**——这类退化在参数日志里完全看不出来。

## 3. 本轮踩到的具体陷阱

### 3.1 封面塌成一个点（`vw` 算错）

```python
vw = w / 1080     # ✗ 1080 画布下 vw == 1.0，于是 "11vw" 真的成了 11px
vw = w / 100      # ✓ vw 是**百分点**，不是「画布宽度的分数」
```

模板里所有尺寸都写成 `N*vw` 时，`vw` 必须等于 `w/100`。
**最阴险的写法**是用一个"看起来像正常缩放比"的值（1.0、0.5）——`w/1080`
在 1080 画布上正好等于 1.0，看着完全无害。

### 3.2 `scan_blank` 的盲区

它只判"接近纯白"，抓得住 `file://` URL 写错导致 Chrome 落 Google 页，抓不住
渲染本身退化。要补两条退化判据：

1. **非背景像素的包围盒**：算与背景色不同的像素的 min/max 边界，框面积 / 画布面积
   低于阈值就判塌。
2. **按设备像素比反查字号**：见 §3.1。

### 3.3 `preroll` 不许小于 0.4s

`feuille karaoke verify-sync` 的 `pre` 探针时刻是**写死的** `scene_start + 0.4`，不从配置读。
把 `preroll` 压到 0.35 省下 2.25s，探针必然越过窗口落到首 token 帧上报
`pre MISMATCH`——**成片其实完全同步，是配置与验收契约打架**。

> 验收脚本里写死的探针常数是配置的**前置条件**，不是可调参数。压任何时长/时距前
> 先问"验收脚本有没有读这个值"；没读就让配置迁就契约，别放宽门禁。

### 3.4 一镜一场景，不是「一段一场景」

段级切分会让 25 个场景各带一次 preroll + done 静默，合计 31s 空白。
**画面在一镜内不变，这正是分镜稿的语义**——镜内分段只用来切 token。

### 3.5 拼接前必须裁尾

直接拼原始 mp3 会带进约 12s 尾部静音（64.3s → 76.4s）。用 ffmpeg
`apad` + `atrim` 按 `effective_dur` 裁，不要改 TTS 那边。

### 3.6 同一行里 ≥2 个外语词时，direction 要加在**装词的容器**上

只给每个词自己加 `dir="rtl"` **只修单个词的字形连写，不修词与词之间的次序**。
装词的那个 flex 容器是 LTR 的话，一句 RTL 语言会以镜像次序显示——
本轮镜 2 的术语行 `مُضَاف إِلَيْهِ` 显示成 مُضَاف 在左、إِلَيْهِ 在右，整句正好倒过来。
是用户一眼看出来的。

```html
<!-- 标记只管单词，不管次序 -->
<div class="termline">
  <span class="ar" dir="rtl">مُضَاف</span><span class="ar" dir="rtl">إِلَيْهِ</span>
</div>
```
```css
.termline { direction: rtl }   /* ← 就这一个属性；.tl 会继承它 */
```

加之前：两个词各自连写正确，整句按容器方向排 → مُضَاف 在左，整句镜像。
加之后：词序翻转，正词组同时落到右边（与 `.compound` 的 dir="rtl" 口径一致）。

**审计判据**：找「直接子元素里含 ≥2 段外语、而自己不是 RTL」的容器。
注意排除**中文句子内嵌单个外语词**（如「就是 جَرْر（属格）的标志」）——那是行内混排，
LTR 才对。判据是"并列多个"，不是"出现外语"。

别拿"每个词渲染正确"当"这一行渲染正确"——前者是逐元素的正确，后者才是版式的
正确，必须放大到整行看。

## 4. 画面语义的三个已确认约定

这些是用户明确要求过的，重做时直接照做，不用再问。

### 4.1 中文注解 / 译文的颜色跟着它标注的阿语词走

不是"辅助信息用灰色"。视觉上等于"这个词是主角、它的中文却是配角"，对比失衡。
实现上让标注函数**按被标注词的 class 派生出译文的 class**，不要写两套 CSS 各自
映射。

### 4.2 卡拉OK 不改颜色

高亮用**底纹 + 不透明度**，不用变色。当一期的主题本身就是颜色对照（金=正词 /
墨=偏词）时，颜色一旦被卡拉OK 占用，这期视频的核心信息就没了。

### 4.3 高亮 key 用坐标，不用词形

同一个偏词在一镜内可能出现三次。用「镜.分段.词」三段坐标做全局唯一 key。
词形当 key 会把多个元素绑到同一个 token 上。

> 相关：`zip(列表A, 列表B)` 会把**更长的那个静默截断**。逐词列表比段数长时，
> 逐词高亮会悄悄退回段级，一切照常渲染、门禁全绿。改按元素自带的段号回表取元数据。
