## 1. 五分钟上手

```bash
cd humming           # 进入 humming 项目根目录（从仓库根目录执行）
npm install          # 首次运行：装 vendor 构建依赖（esbuild / tfjs）
cargo tauri build    # 打包桌面应用
```

产物位于：

```
src-tauri/target/release/bundle/macos/HummingScore.app
src-tauri/target/release/bundle/dmg/HummingScore_1.0.0_aarch64.dmg
```

双击 `.app` 启动，或把 `.dmg` 拖入「应用程序」。

**不想打包？** 直接运行开发模式：

```bash
cargo tauri dev      # 改前端代码即时生效
npm run serve        # 仅浏览器调试，访问 http://127.0.0.1:3000
```

> 应用**完全本地运行**：转谱推理在应用内完成，不联网、不需要 Python。

## 2. 界面总览

界面自上而下分为五个区域：

| 区域 | 作用 |
| --- | --- |
| **顶部状态栏** | 显示当前引擎、进度与结果摘要；启动异常也会在此提示 |
| **控制栏** | 录音、导入、引擎选择、节拍器、BPM、拍号、量化网格 |
| **实时监控屏** | 录音时的示波器、音高调音计（音名/Hz/音分）、VU 电平表、VAD 状态 |
| **流水线面板** | 识谱过程中逐阶段显示状态与量化指标（识谱后出现） |
| **乐谱工作区** | 视图切换、试听/导出、音符芯片时间轴、五线谱、简谱、钢琴卷帘 |

## 3. 三种录音/导入方式

### 方式 A：现场哼唱录音

1. 点击 **「开始哼唱录音」**，首次运行会请求麦克风权限（请点「允许」）。
2. 监控屏实时显示波形、音名与电平；跟着节拍器哼唱节奏更稳。
3. 再次点击按钮停止，系统自动完成识谱并渲染乐谱。

> **建议**：先开启「节拍器」并设定 BPM，哼出的节奏更规整，量化误差更小。

### 方式 B：导入音频文件

支持 `.m4a`（iPhone 语音备忘录默认格式）、`.wav`、`.mp3`、`.aac`、`.ogg`。

- 点击 **「📥 载入 m4a / 录音文件」** 选择本地文件
- 或**直接把文件拖拽**到窗口任意位置
- 或点击 **「📱 载入内置 m4a 样本」** 使用随附的 `demo_twinkle.m4a`

载入后：
1. 点击 **「▶ 播放原声」** 试听，可拖拽进度条定位
2. 点击绿色的 **「🎼 开始识谱 (Transcribe to Score)」** 执行转谱

### 方式 C：预置示例（推荐首次试用）

点击 **「✨ 快速测试示例」** 中的任一按钮，音频会在本地实时合成，无需任何文件：

| 按钮 | 曲目 |
| --- | --- |
| ⭐ 《小星星》 | 1 1 5 5 6 6 5 - … |
| 🐯 《两只老虎》 | 1 2 3 1 1 2 3 1 … |
| 🎼 《欢乐颂》 | 3 3 4 5 5 4 3 2 … |
| 🎂 《生日快乐》 | 5 5 6 5 1 1 5 … |

点击后立即执行完整流水线，是验证功能是否正常的最快方式。

## 4. 选择转谱引擎

在控制栏「转谱引擎」下拉框中切换：

| 引擎 | 适用场景 | 说明 |
| --- | --- | --- |
| 🧠 **Spotify Basic Pitch**（默认） | 多音、合唱、乐器 | 内置 tfjs 神经网络，多音识别最强。**无需联网** |
| 🎵 **Google Magenta SPICE** | 单音清唱 | 针对单音人声优化，哼唱旋律较干净时更准 |
| 🎙️ **pYIN + Viterbi** | 快速预览 | 纯 DSP 本地算法，零依赖、极速，适合先看个大概 |

> **引擎回退是自动的**：若所选引擎不可用，系统会回退到 pYIN。
> 状态栏会**如实显示实际使用的引擎**，不会谎报来源。

## 5. 看懂五阶段流水线

识谱过程中，控制栏下方会展开流水线面板，逐阶段点亮并显示量化指标：

| 阶段 | 处理内容 | 显示的指标 |
| --- | --- | --- |
| ① **音频预处理** | 峰值增益规整、重采样 16kHz、80–2000Hz 带通滤波、VAD 人声端点检测 | 采样率、滤波带通、人声区间、过滤掉的杂音时长 |
| ② **声学转谱引擎** | 调度所选引擎提取 Pitch Contour 与 Onset 概率矩阵 | 实际使用的引擎名 |
| ③ **音符切分与量化** | 中值去颤音、120ms 滑音合并、节拍网格吸附 | 原始微片段数、滑音门限、量化网格、最终音符数 |
| ④ **调性推断与分小节** | Krumhansl-Schmuckler 24 大小调余弦相似度匹配 | 主调式、调号、小节数、前三调性相关度 |
| ⑤ **乐谱渲染与导出** | 矢量五线谱、首调简谱、钢琴卷帘 | 全链路耗时 |

面板右上角汇总**本次识谱的总耗时**（毫秒）。

## 6. 乐谱视图与播放

### 视图切换

顶部 Tabs 提供四种视图：

- **五线谱 + 简谱** —— 默认，上下对照
- **纯五线谱 (Staff)** —— 高保真矢量排版
- **纯简谱 (Jianpu)** —— 首调唱名法（1=C、1=G）
- **钢琴卷帘 (Piano Roll)** —— **青色曲线**为连续 F0 轨迹，**绿色方块**为量化后的音符，用于核对切分是否合理

### 播放

| 按钮 | 效果 |
| --- | --- |
| ▶ **试听乐谱 (MIDI Synth)** | 拟真钢琴合成器走带播放识别结果，播放头随音符高亮 |
| 🔊 **对照原声** | 播放原始录音，与乐谱对照核查 |

## 7. 导出 MIDI / MusicXML

识谱完成后，两个导出按钮会自动解除禁用状态：

| 格式 | 用途 | 导入目标 |
| --- | --- | --- |
| **MIDI (`.mid`)** | 继续编辑、编曲、制作 | Logic Pro、Cubase、FL Studio 等任意 DAW |
| **MusicXML (`.musicxml`)** | 重新制谱、出版排版 | MuseScore、Sibelius、Finale 等制谱软件 |

> 导出后顶部状态栏会提示文件名与内容摘要（如音符数 / 小节数）。
> 若无可导出内容或导出失败，状态栏会明确说明原因。

## 8. 音符微调与快捷键

### 进入编辑模式

- **点击乐谱中任意音符**，或
- 点击音符芯片时间轴中的任一芯片

编辑后工具栏与时间轴会自动高亮当前音符。

### 编辑工具栏

| 分组 | 可用操作 |
| --- | --- |
| **音高选择** | 下拉直接指定音名八度；半音 ↑/↓；八度 ↑/↓ |
| **时值选择** | 全音符 / 二分 / 四分 / 八分 / 十六分；附点开关 |
| **结构增删** | 插入音符、插入 1 拍休止符、删除当前音符 |

### 快捷键

| 快捷键 | 功能 |
| --- | --- |
| `←` / `→` | 选择上一个 / 下一个音符 |
| `↑` / `↓` | 升 / 降半音 |
| `Shift` + `↑` / `↓` | 升 / 降八度 |
| `空格` | 试听当前选中音符 |
| `Delete` / `Backspace` | 删除当前音符 |

> 焦点位于下拉框、输入框或按钮上时，快捷键自动让位给该控件，
> 避免在选择音高时误改音符。

### 调整 BPM / 拍号 / 网格

改动后乐谱会**实时重算并重新渲染**，无需重新识谱：

- **BPM**：影响节拍网格与量化时长（带 150ms 防抖，拖动流畅）
- **拍号**：4/4、3/4、2/4，影响小节划分
- **网格**：八分（1/2 拍）、十六分（1/4 拍）、四分（1 拍），影响量化精度

## 9. 常见问题排查

<details>
<summary><b>构建报错 <code>error running bundle_dmg.sh</code>？</b></summary>

这是 **DMG 打包**阶段失败（`.app` 本身通常已构建成功）。常见原因与处理：

- **报 <code>No space left on device</code>**：create-dmg 的临时镜像 `rw.*.dmg` 残留在
  `src-tauri/target/release/bundle/macos/` 中，被当作内容算进下一次打包，
  形成**自我延续的失败循环**（一次失败后每次构建都失败）。执行
  `node scripts/clean_bundle_state.mjs` 清理后重试即可。
  本项目已在 `beforeBuildCommand` 中自动执行该清理。
- **报卷被占用 / 无法卸载**：有应用正运行在挂载的临时卷中。关闭该应用后执行
  `hdiutil detach /Volumes/dmg.XXXX -force`，再重试。
- **只想快速拿到可用的 <code>.app</code>、不需要 DMG**：
  ```bash
  cargo tauri build --bundles app
  ```
</details>

<details>
<summary><b>点击「试听乐谱」没有声音？</b></summary>

- 确认 macOS **输出设备**有音量且未被静音（系统声音设置 → 输出）。
- 确认没有静音运行应用；应用无独立音量滑杆，输出到系统当前默认设备。
- 若提示「试听失败：系统音频输出不可用」，说明 AudioContext 无法启动，
  通常是音频设备被独占（如被其他应用占用）或系统音频服务异常。
- 重新识谱后再试：按钮在识谱完成前是禁用状态，此时点击不会有反应。
</details>

<details>
<summary><b>点击按钮没有任何反应？</b></summary>

查看顶部状态栏。若显示「启动异常」或「音频不可用」，说明运行环境缺少 Web Audio
（无音频输出设备或受限环境）。此时请检查系统音频输出设备是否正常。
应用已做容错：音频不可用时仍会明确提示，而非静默失效。
</details>

<details>
<summary><b>识别结果音符太多 / 太少？</b></summary>

依次尝试：
1. 调整**量化网格**（十六分音符网格会产生更多音符）
2. 调整 **BPM** 使哼唱节奏与网格匹配
3. 换用 **SPICE** 引擎（单音场景更干净）
4. 用音符编辑工具手动删除误识别的碎音
</details>

<details>
<summary><b>识别不准、有明显错音？</b></summary>

- 录音时环境噪音越小越好（VAD 会切除静音段，但持续底噪会影响音高判定）
- 确认选择的是正确的**拍号**
- 哼唱时避免大幅滑音，滑音会被 120ms 门限合并
</details>

<details>
<summary><b>Basic Pitch 引擎提示回退到 pYIN？</b></summary>

说明内置神经网络推理未能产出结果（常见于音频过短、几乎全静音）。
应用会自动回退并在状态栏标明。延长录音或提高音量可改善。
</details>

<details>
<summary><b>导出的文件打不开？</b></summary>

- `.mid` 请用任意 DAW 打开
- `.musicxml` 请用 MuseScore / Sibelius 打开（部分简易编辑器不支持 3.1 规范）
</details>

<details>
<summary><b>改了前端代码但应用没变化？</b></summary>

```bash
cargo tauri dev        # 开发模式：前端改动热重载，无需任何同步步骤
```

若改动涉及 vendor 依赖或入口文件，用 `npm run build:vendor` 重建；
`cargo tauri dev` 启动时也会自动跑一次（幂等，产物未变则跳过）。

以前需要「先同步到 `src-tauri/www/` 再启动」，现在前端源码目录就是打包目录
（`frontendDist` 指向 `src/`），不存在同步步骤，也就没有同步过期的问题。
</details>

## 10. 命令速查表

| 命令 | 执行目录 | 作用 |
| --- | --- | --- |
| `cargo tauri dev` | 根 | 桌面应用开发模式（自动构建 vendor，前端热重载） |
| `cargo tauri build` | 根 | 打包 `.app` + `.dmg`（或其他平台安装包） |
| `npm test` | 根 | 运行全部前端测试（声学流水线 + 乐理编辑 + 试听链路 + 界面契约） |
| `npm run build:vendor` | 根 | 单独重建 Basic Pitch vendor bundle 与模型 |
| `npm run serve` | 根 | 仅启动本地静态服务（浏览器调试） |
| `npm install` | 根 | 首次安装 vendor 构建依赖 |

### 测试覆盖

| 测试文件 | 覆盖内容 |
| --- | --- |
| `tests/test_pipeline.mjs` | 三种转谱引擎的音符提取、调性推断、MIDI/MusicXML 导出 |
| `tests/test_note_editor.mjs` | 乐理与音符编辑：音高修改、时值对齐、小节划分、增删音符 |
| `tests/test_synthesizer.mjs` | 试听链路：发声拓扑、音符时序、音高换算、停止复位、suspended 上下文恢复 |
| `tests/test_ui_contract.mjs` | 界面契约：确保 `main.js` 引用的元素 id 与样式在 `index.html`/CSS 中真实存在 |

> 界面契约测试用于防止一类隐蔽回归：元素 id 缺失时事件监听会被静默跳过，
> 界面照常渲染但按钮全部失效，且控制台无任何报错。
