# 工程标准化改造

日期：2026-10-07
状态：已完成

把本工程与同工作区的 `reading`（Ready Reader）统一到 Tauri 官方
`create-tauri-app` vanilla 模板结构，共用同一套构建入口与文档分层。

---

## 1. 改造前的差异

| 维度 | 改造前 | 问题 |
| --- | --- | --- |
| 前端源码 | 仓库根级 `index.html` + `css/` + `js/` | 偏离 Tauri 模板；构建产物与源码目录混排 |
| `frontendDist` | `src-tauri/www/` | 需要 `scripts/copy_frontend.mjs` 维护一份副本 |
| 同步机制 | SHA-1 内容哈希比对后复制 | 脚本失效即静默打包过期内容；双份源码必然漂移 |
| 入口 | `npm run tauri:dev` / `npm run build:tauri` | 与 `reading` 的 `cargo tauri` 不一致 |
| 测试 | 仓库根级 `test_*.mjs` | 与业务文件混排 |
| 文档 | 根级 `README.md` + 根级 `USAGE.md` | 两份说明文档都在根目录，与 `reading` 的 `docs/` 分层不一致 |
| 图标源 | `scripts/make_icon.html` | 不在 `src-tauri/assets/` 的标准位置 |

## 2. 执行动作

### 前端源码迁移到 `src/`

| 改造前 | 改造后 |
| --- | --- |
| `index.html` | `src/index.html` |
| `js/app.js` | `src/main.js`（入口脚本改名，与模板一致） |
| `js/{dsp,audio,render,export,theory,vendor}/` | `src/{dsp,audio,render,export,theory,vendor}/` |
| `css/style.css` | `src/css/style.css` |
| `demo_twinkle.m4a` | `src/assets/demo_twinkle.m4a` |
| `scripts/make_icon.html` | `src-tauri/assets/icon_source.html` |

模块间全部使用相对路径 `import`，因此只改了 `index.html` 的两行引用与
`main.js` 里 `fetch('/demo_twinkle.m4a')` 一处，**无需修改任何 import 语句**。
`scripts/serve.mjs` 的根路径映射改为 `/src/index.html`。

根目录收口：原根级的 `server.js` 是唯一没有存在理由的散落文件（`package.json` /
`scripts/` / `tests/` 分别由前端构建链、构建脚本、Node 测试所需，
`src-tauri/Info.plist` 是 macOS 麦克风权限所需，均为必要项），已移入
`scripts/serve.mjs`，服务根改为仓库根。移入后根目录除 `README.md` 外只剩
目录与 `package.json` / `package-lock.json`。

### 配置

- `tauri.conf.json`：`frontendDist` 由 `www` 改为 `../src`；
  新增 `beforeDevCommand` / `beforeBuildCommand`，均指向 `node scripts/build_vendor.mjs`。
- 删除 `scripts/copy_frontend.mjs` 与 `src-tauri/www/` 整棵副本。
- `scripts/build_vendor.mjs`：产物路径改为 `src/vendor/`，
  入口改为 `src/dsp/basic_pitch_entry.js`；缺 esbuild 时给出明确的 `npm install` 提示。
- `package.json`：移除 `@tauri-apps/cli`（入口统一走 `cargo tauri`，避免第二条竞争路径）、
  移除 `build:frontend` 等失效脚本，`start` 收敛为 `serve`，加 `private: true`。
- `.gitignore`：vendor 产物路径更新为 `src/vendor/`；
  `src-tauri/gen/` 不再忽略——`capabilities/default.json` 的 `$schema` 指向它，
  跟踪后新克隆无需先构建即可在编辑器里校验 JSON。

### 测试适配

仓库根级的 `test_*.mjs` 移入 `tests/`，文件名去掉 `test_` 前缀改为
`tests/test_*.mjs`（与 Tauri 模板的 `src-tauri/tests/` 同构）。
测试内部引用全部是相对路径，随目录整体迁移即可。

`tests/test_ui_contract.mjs` 扫描 `main.js` 的 `document.getElementById()` 调用，
逐项核对 id 是否真实存在于 `index.html`。该测试的存在意义是防止一类隐蔽回归：
id 缺失时监听器会被可选链 `?.` **静默跳过**，表现为「界面正常渲染但按钮点了没反应」
且控制台无任何报错。

### 文档

- 根级 `USAGE.md` → `docs/使用指南.md`。
- 新增 `docs/设计/架构.md`：从 README 抽出模块职责与关键技术决策。
- 本文件 → `docs/计划/2026-10-07-工程标准化.md`。
- README 重写：统一命令表（与 `reading` 同构）、新目录树、
  「与标准的差异」小节显式记录本工程偏离模板的 8 处及其理由。
