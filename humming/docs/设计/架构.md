# 哼唱识谱架构说明

日期：2026-10-07
状态：长期维护

本文说明 HummingScore 的内部结构与关键技术决策。面向使用者的操作说明见
[使用指南.md](../使用指南.md)。

---

## 1. 总体形态

```
Tauri 2 App (Rust 外壳)
├─ src/                纯静态前端，无框架、无打包器，直接由 webview 加载
│  └─ vendor/          esbuild 预打包的 Basic Pitch + tfjs（构建产物）
└─ 后端职责：无
```

Rust 侧只提供窗口与 WebView，不注册任何 command、不开端口、不做业务计算。
所有转谱推理在 webview 内以 tfjs 本地完成，因此：

- 不需要 Python、不需要本地 HTTP 服务、不占端口
- 不联网（模型权重随包分发）
- `capabilities/default.json` 只需 `core:default`，麦克风由 WebAudio `getUserMedia`
  走系统权限与 `src-tauri/Info.plist` 的 `NSMicrophoneUsageDescription`

## 2. 五阶段转谱流水线

```
① 采集/解码 (WebAudio)
     ↓
② 声学转谱引擎  (Basic Pitch / SPICE / pYIN+Viterbi)
     ↓  Pitch Contour + Onset 概率矩阵
③ 切分与量化    (中值去颤音 → 滑音合并 → 节拍网格吸附)
     ↓  结构化音符序列
④ 调性推断      (Krumhansl-Schmuckler 24 大小调余弦相似度)
     ↓  主调式 + 调号 + 小节划分
⑤ 乐谱渲染与导出 (矢量五线谱 / 首调简谱 / 钢琴卷帘 + MIDI / MusicXML)
```

流水线面板逐阶段点亮并显示量化指标，状态栏如实显示**实际使用的引擎**——
所选引擎不可用时自动回退 pYIN，绝不谎报来源。

## 3. 模块职责

| 目录 | 职责 |
| --- | --- |
| `src/main.js` | 主控制器：状态机、事件绑定、流水线编排、状态栏反馈 |
| `src/dsp/preprocessor.js` | 峰值增益规整、重采样 16kHz、80–2000Hz 带通、VAD 端点检测 |
| `src/dsp/pitch_tracker.js` | pYIN 基频追踪 |
| `src/dsp/segmentation.js` | 音符切分、滑音合并、节拍网格量化 |
| `src/dsp/ai_transcription_engine.js` | 三引擎调度与回退 |
| `src/dsp/basic_pitch_entry.js` | Basic Pitch 的 esbuild 入口 |
| `src/audio/metronome.js` | 节拍器（BPM / 拍号） |
| `src/audio/recorder_monitor.js` | 示波器、调音计（音名/Hz/音分）、VU 表 |
| `src/audio/synthesizer.js` | 拟真钢琴合成器，试听走带播放 |
| `src/audio/samples.js` | 内置示例音频实时合成 |
| `src/render/*.js` | 五线谱 / 简谱 / 钢琴卷帘渲染器 |
| `src/export/*.js` | MIDI 与 MusicXML 导出器 |
| `src/theory/krumhansl.js` | 调性推断与小节划分 |
| `src/vendor/` | 构建产物：`basic-pitch.bundle.js` + TFJS 模型 |

模块间一律用相对路径 `import`，因此前端目录可以整体改名或迁移而不动 import 语句。

## 4. 关键技术决策

### 4.1 推理后端：WebGL 优先，不采用 WASM

tfjs 3.21 的 wasm 后端缺少 `tf.signal.frame` 算子，而 Basic Pitch 的 `prepareData`
依赖该算子，会抛 `Unknown dtype undefined`。实测 WebGL 后端可用且最快
（1s 音频约 0.7s），不可用时回退 CPU。

### 4.2 推理位置：主线程，不用 Web Worker

实测 tfjs 的 WebGL 计算在 Worker 中会挂起（0.3s 音频卡死 >60s），
且 macOS WKWebView 基本不支持 Worker 内 WebGL。tfjs 的 GPU 调用均为 async，
主线程会在 GPU 操作之间让出，界面不会冻结。

### 4.3 vendor 产物不进版本管理，但必须先于运行生成

`src/vendor/` 是 gitignored 的构建产物，由 `scripts/build_vendor.mjs` 生成，
挂在 `beforeDevCommand` / `beforeBuildCommand` 上。脚本按「入口与依赖包 mtime」
增量判断，源未变则跳过，幂等。

### 4.4 不保留前端产物副本

历史实现把 `src/` 复制到 `src-tauri/www/` 供 Tauri 打包，靠 SHA-1 内容哈希判断同步。
该方案的固有缺陷是：同步脚本一旦失效就会静默把过期内容打进发布包，
且双份源码必然漂移。现在 `frontendDist` 直接指向 `src/`，
前端资源在打包时内嵌进二进制，不存在副本与同步问题。

### 4.5 CSP 放行 `'unsafe-eval'` 与 `blob:`

tfjs 需要动态代码求值，`vendor/basic-pitch-model` 通过 Blob URL 加载权重。
CSP 在 `src-tauri/tauri.conf.json` 中相应放行，其余指令保持 `default-src 'self'`。

## 5. 测试策略

| 层 | 位置 | 覆盖 |
| --- | --- | --- |
| 声学与乐理 | `tests/test_*.mjs` | 三引擎音符提取、调性推断、导出器、音符编辑、试听链路 |
| 界面契约 | `tests/test_ui_contract.mjs` | `main.js` 引用的元素 id 与 CSS 类必须在 `index.html` / 样式表中真实存在 |

界面契约测试针对一类隐蔽回归：`document.getElementById()` 取不到元素时，
事件监听被可选链静默跳过，界面照常渲染但按钮全部失效且控制台无任何报错。
`npm test` 在提交前应全绿。
