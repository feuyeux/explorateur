# Ready Reader 使用指南

面向日常使用的完整操作说明。安装与架构细节见 [README](../README.md)。

---

## 1. 启动应用

### 前置要求

只有**从源码运行**才需要以下依赖；用安装包直接装好即用。

| 依赖 | 版本 | 检查 / 安装 |
|---|---|---|
| Rust | 1.77+ | `rustc --version` |
| tauri-cli | 2.x | `cargo install tauri-cli --version "^2"`，或 `brew install tauri-cli` |
| Xcode 命令行工具 | — | macOS：`xcode-select --install` |
| webkit2gtk-4.1 等 | — | 仅 Linux，见 [Tauri 官方文档](https://tauri.app/start/prerequisites/) |

前端是原生 HTML/CSS/JS，**没有 npm 依赖、没有构建步骤**，不需要装 Node。

### 三种启动方式

**方式一：启动已构建好的 app**

本机已有构建产物，直接启动即可：

```bash
cd reading               # 进入 reading 项目根目录（从仓库根目录执行）
open "src-tauri/target/release/bundle/macos/Ready Reader.app"
```

> ⚠️ 两个前提：
> - **必须在项目根目录（`reading/`）执行。** 上面那条是相对路径，在别的目录执行会被解析成
>   `<当前目录>/src-tauri/...`，报 `does not exist`。
> - **产物是本机私有的。** `src-tauri/target/` 被 `.gitignore` 排除，不随仓库分发；
>   换机器或重新克隆后此方式不可用，请走方式二或方式三。
>
> 构建产物是上一次 `cargo tauri build` 的快照，**总是落后于当前源码**。
> 若界面或功能与源码对不上，用方式三重新构建。

想让它出现在「应用程序」里：把该 `.app` 拖进 `/Applications`。

**方式二：开发模式（要改代码就用这个）**

```bash
cd /path/to/ready        # 必须在仓库根目录执行
cargo tauri dev
```

首次运行会编译依赖，耗时较长。开发模式开启了文件监听：`src/` 下的改动直接热重载；改 Rust 代码会自动重新编译并重启应用（比前端改动慢）。

**方式三：重新打包**

```bash
cd /path/to/ready
cargo tauri build
```

产物按平台而定：macOS 生成 `macos/Ready Reader.app` 与 `dmg/Ready Reader_<版本>_<架构>.dmg`；在 Linux 上构建则生成 `deb/` 与 `appimage/`。

> 命令一律在**仓库根目录**执行：tauri-cli 从当前目录及其上级查找 `tauri.conf.json`，并回退到 `src-tauri/`。在 `src-tauri/` 目录里直接跑反而定位不到配置。

### 首次启动会发生什么

1. 在应用数据目录自动创建数据库（路径见第 9 节）
2. 若库中没有任何原著，自动载入《白鲸记》样例
3. **未配置 API Key 时使用内置离线演示引擎**，无需任何配置即可上手
4. 从源码启动且数据库尚不存在时，会自动迁移 `legacy-backup/` 里的旧库（见第 9 节）

### 启动相关排查

| 现象 | 原因 / 处理 |
|---|---|
| `error: no such command: tauri` | 没装 tauri-cli：`cargo install tauri-cli --version "^2"` |
| 提示找不到 `tauri.conf.json` | 没在仓库根目录执行 |
| 编译报 `webkit2gtk` 缺失 | 仅 Linux，补装系统依赖 |
| macOS 提示「无法验证开发者」 | 本地未签名构建：右键 `.app` → 打开，或 `xattr -dr com.apple.quarantine "path/to/Ready Reader.app"` |
| 窗口打开但一片空白 | 确认在仓库根目录启动；打开开发者工具看控制台报错 |
| 想彻底重来 | 删除数据目录里的 `ready_reader.db`（见第 9 节） |

## 2. 五分钟上手

1. 启动 Ready Reader（见第 1 节）。
2. 点任意段落右上的 **⚡ 一键解析本段**，右栏立刻出现逐句精译。
3. **点击**左栏任一句子，右侧「语法透视镜」展开句法切片、语境词义与典故。
4. 看到想记住的词，点词条旁的 **+ 加入生词本**。
5. 顶栏 **📚 生词本 & Anki** → **⚡ 一键导出至 Anki**，存盘后到 Anki 里导入。

全程无需配置任何 API Key——未配置时使用内置离线演示引擎。

## 3. 导入原著

### 支持的格式

`.md` / `.markdown` / `.txt`，**必须是 UTF-8 编码**。文件类型由后端校验：文件选择框的过滤器和 `accept=` 只是界面装饰，拖拽进来一样会被后端拒绝。

### 导入时发生了什么

Markdown 标记会被自动清洗，**空行分段结构完整保留**（段落边界就是你的阅读单位）：

| 原文写法 | 处理结果 |
|---|---|
| `# 标题` | 去掉 `#` 标记，文字保留 |
| `> 引用` | 去掉 `>` 标记 |
| `**粗体**` / `*斜体*` / `_斜体_` | 去掉标记 |
| `` `行内代码` `` | 保留文字内容 |
| `[链接文字](url)` | 保留「链接文字」 |
| `![图片说明](url)` | 保留「图片说明」 |
| ` ```代码块``` ` | 整块删除 |

### 被拒绝的情况

- **空文件**或只有空白字符
- **编码异常**：解码后出现大量替换字符 `�`（超过全文 0.5%）。通常是 GBK 等非 UTF-8 编码被误读，请用编辑器「另存为 UTF-8」后重试

被拒绝的文件**不会写入任何数据**，不会有半截文档残留在库里。

### 内置样例

《白鲸记》《了不起的盖茨比》第一章已内嵌在二进制中，顶栏按钮随时可重新加载。两本样例都**预置了术语表**（人名译名全书统一），可以直接体验术语表的效果。

## 4. 精读与解析

### 段落级

段落右上 **⚡ 一键解析本段** → 右栏逐句生成精译，段落标记变为 **✓ 已对齐**。整段一次调用模型，比逐句点便宜也更快。

### 句子级联动

- 鼠标**悬停**任意句子，左右栏对应句同步高亮
- **点击**句子打开右侧「语法透视镜」，同时该句在双栏中被标记为当前句

### 语法透视镜包含什么

| 区块 | 内容 |
|---|---|
| 句法主干切片 | 主干成分逐个徽章展示（S / V / O / IO / DO / OC / Adv / Attr / 从句） |
| 词法速查 | 重点词的**当前语境**释义，不是词典泛义 |
| 典故解析 | 成语、隐喻、文化背景 |
| 🔊 发音 | 调用系统语音朗读该句 |

### 缓存与预取

- 整段解析结果与单句深度分析**分别缓存**，重复阅读不再调用模型，也不额外花钱
- 点击某句后，**下一段会在后台自动预取**，连续阅读基本无等待
- 若模型对某句返回空译文，该句**不会写入缓存**，下次点击会重试，不会永久显示空白

## 5. 生词本与 Anki 导出

### 收藏与查看

顶栏 **📚 生词本 & Anki** 打开列表，显示词汇、词性、语境释义、出处语境与收藏时间，可逐条删除。

### 导出

点 **⚡ 一键导出至 Anki (TSV/CSV)** → 选保存位置（默认文件名 `ready_reader_anki_cards.txt`）→ Rust 直接在目标路径生成文件。

### 在 Anki 中导入

文件 → 导入 → 选择该文件，字段分隔符选 **Tab**，勾选「允许 HTML」，导入成功。

导出的每行固定 **5 列**：

| 列 | 内容 |
|---|---|
| 1 | 正面：加粗大字 + 灰色斜体出处语境（词条在语境中高亮） |
| 2 | 背面：词性标签 + 释义 + 文化背景 |
| 3 | 词汇（纯文本） |
| 4 | 语境释义（纯文本） |
| 5 | 标签：`ReadyReader ForeignLiterature`（对应文件头的 `#tags column:5`） |

### 两个容易踩的坑

1. **字段分隔符必须选 Tab**，选逗号会整份错位。
2. **换行与制表符已被折叠为空格**。Anki 的 TSV 导入器不处理引号，无法转义含换行的字段——所以导出时就把它们换成了空格（HTML 渲染效果不变）。如果你看到某张卡的释义挤在一行，就是原本含换行，属正常。

## 6. 全文翻译与解析（一次跑完整本书）

顶栏 **⚡ 全文翻译** 一次跑完整本书：先把所有段落翻译出来，再为每一句做深度解析（语法透视镜那些内容）。跑完直接导出。

| | |
|---|---|
| **执行顺序** | 先全部段落翻译 → 全部句子深度解析。句子阶段等段落阶段完全结束才开始，因为深度解析要读所属段落 |
| **并发** | 3 个请求同时跑。再高容易撞上服务商的限流，限流会把「慢」变成「失败」 |
| **可中断** | 随时点「停止」。已完成的段落和句子都已落库，不会白跑 |
| **可续跑** | 已翻译的段落、已分析的句子会自动跳过。中断后重跑只补缺口 |
| **进度** | 弹窗显示进度条、当前处理到哪一条、失败计数；失败项在结束时列出最后一次错误原因 |
| **结束** | 自动刷新阅读面板，可以直接点 **📄 导出 Markdown** |

**它会拒绝在离线演示模式下启动**，并提示先去配置模型。原因很实在：离线引擎会瞬间返回
`【译文】+原文`，一次全文跑完产出的只是几百条占位符——白花时间，还看不到真译文。
（占位符也不会进缓存：启动时会自动清理历史占位行，阅读判定与 Markdown 导出都不会把它们当真译文。）

> ⚠️ 这是**花钱**的操作：一本书可能有几百次模型调用。开始前会弹确认。
> 跑之前建议先用一两段试一下，确认译文质量满意再全书运行。

## 7. 导出译文与解析（Markdown）

顶栏 **📄 导出 Markdown** 把当前原著导出成一份 `.md`：YAML front matter +
按段分节的**原文/译文逐句对照** + 每句已缓存的语法透视镜解析（句法切片、语境词义、
典故、基调）。

- **范围是全书**，但**只导已解析的段落**——没点过「一键解析本段」的段落不会出现，
  文件因此永远是「已翻译部分」的忠实副本，而不是一本假装完整却到处是原文的书。
- 文件头会写明进度：`已解析 3/40 段 · 82 句译文`，一眼能看出还差多少。
- 段落编号沿用原文的真实位置（`## 第 17 段`），跳过的段落会留下编号空洞，
  便于对照原书定位。
- **导出只读缓存，不会触发任何模型调用**，也不消耗额度，随时可导。
- 译文栏用 Markdown 引用块（`>`）渲染，多行译文不会掉出引用块。

导出样例（用书里内置的白鲸记样例跑出来的真实结果）：

```markdown
---
title: "白鲸记 (Moby-Dick)"
author: "Herman Melville"
paragraphs_exported: 1
paragraphs_total: 4
sentences_exported: 1
---

## 第 4 段

**1.** Call me Ishmael.

> 叫我以实玛利吧。

- **句法** 祈使句 (Imperative sentence)
  - `Call` — 谓语动词 (V)
  - `me` — 宾语 (O)
  - `Ishmael` — 宾语补足语 (OC)
- **词法**
  - **Ishmael**（专有名词） 人名（以实玛利）
    - 《圣经·创世记》中亚伯拉罕之子，后常引申指代被放逐者、孤立于世的流浪汉。
- **典故**
  - **Call me [Name]** — 常用于非正式的自我介绍，此处开篇弱化了说话者的身份界限……
- **基调** 简洁而带有叙事宿命感的开篇第一人称独白
```

> 离线演示引擎的占位译文（形如 `【译文】Call me Ishmael.`）**不会**被导出：它们不进缓存，
> 历史占位行会在启动时被清掉，导出的过滤条件与阅读判定一致。

## 8. 配置 LLM（可选）

不配置也能用：未填 API Key 时自动使用**内置离线演示引擎**——经典段落给出预置精译，其余句子做 S-V-O 启发式切片。零配置、零成本，适合先熟悉界面。

要获得真正的整段翻译与深度解析：

1. 顶栏 **⚙️ 设置**
2. 选择提供商（切换时模型输入框会自动填入该提供商的默认模型）
3. 填 **API Key**（只写入本机 SQLite，不上传任何第三方服务器）
4. Base URL 留空即用官方端点；温度默认 `0.2`
5. 点 **保存配置**

| 提供商 | 默认端点 | 默认模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-1.5-flash` |
| Anthropic Claude | `https://api.anthropic.com/v1` | `claude-3-5-sonnet` |
| MiniMax | `https://api.minimaxi.com/anthropic/v1` | `MiniMax-M3` |
| 自定义兼容端点（Ollama 等） | 你填写的 Base URL | 同上表对应提供商 |

> **MiniMax 的 Base URL 必须带 `/v1`。** 应用会在 Base URL 后面直接拼 `/messages`，
> 所以要填 `https://api.minimaxi.com/anthropic/v1`；填成不带 `/v1` 的
> `https://api.minimaxi.com/anthropic` 会打到 `/anthropic/messages`，服务端返回 404。
> （Claude Code 里配的 `ANTHROPIC_BASE_URL` 不带 `/v1` 是因为 Anthropic SDK 自己会补。）
>
> **模型名不要加 `minimax/` 前缀。** MiniMax 自家 API 的模型 id 是 `MiniMax-M3`；
> `minimax/MiniMax-M3` 是 OpenRouter 的路由写法，在 MiniMax 端点会 404。
> 可用模型以 `GET https://api.minimaxi.com/v1/models` 返回的列表为准。

> **模型名留空 = 用该提供商的默认模型。** 自定义端点同样如此：把 Claude 指向代理并把模型框清空，程序会发 `claude-3-5-sonnet`，而不是硬塞一个 OpenAI 模型名过去。

**解析失败会自动回退离线引擎**，阅读不会中断——回退不再静默：段落解析完成时会弹红色提示并附上失败原因，全文翻译也会把回退项计入失败计数。如果配置了 Key 却反复看到这类提示，多半是端点或 Key 有问题，见第 10 节。

## 9. 数据、备份与重置

| 平台 | 数据库路径 |
|---|---|
| macOS | `~/Library/Application Support/com.ready.reader/ready_reader.db` |
| Windows | `%APPDATA%\com.ready.reader\ready_reader.db` |
| Linux | `~/.local/share/com.ready.reader/ready_reader.db` |

- **备份**：直接复制这个 `.db` 文件即可（含文档、生词本、术语表、配置）
- **重置**：删除该文件，下次启动重新初始化
- 所有数据与 API Key 都只留在本机，不经过任何服务器

### 从旧版（Python 后端）迁移

本仓库已移除 Python 后端，但它留下的数据库保留在 `legacy-backup/data/ready_reader.db`。**首次启动**时若应用数据目录还没有数据库，程序会自动把它复制过去，生词本与已有译文随之保留。

同时兼容更早的 `<项目>/data/ready_reader.db` 位置；两处都存在时优先用仓库内的那份。

> 迁移只在「目标数据库不存在」时触发，且只对从源码运行（`cargo tauri dev`）有效——安装包运行时已经迁移过了。确认数据已迁移成功后即可删除 `legacy-backup/`。

## 10. 常见问题

**导入后提示「文件编码异常」**
文件不是 UTF-8。用编辑器打开 → 另存为 → 选 UTF-8。

**提示「暂不支持 .pdf / .epub 文件」**
本版本只支持 `.md` / `.markdown` / `.txt` 纯文本。先用转换工具转成 txt 或 md。

**点了「一键解析本段」按钮一直转圈 / 没反应**
打开开发者工具看控制台。正常情况下按钮会先变成「⏳ 正在拆解分析...」。若卡死说明后端异常，重启应用。

**配了 API Key，但译文还是「【译文】xxx」这种启发式内容**
说明调用失败并回退了离线引擎——完成提示里会带具体失败原因。检查：API Key 是否正确、Base URL 是否多了 `/v1/chat/completions` 之类的后缀（只填到 `/v1` 即可，程序自己拼路径）、模型名是否与账号可用模型一致。Claude 与 MiniMax 走的是 Anthropic 原生消息格式，程序会自动切换。修好后重新点「一键解析本段」即可——曾经被占位符占过的段落不会被缓存卡住，会重新走模型。

**生词本里的词导不出 / 卡片错位**
导入时字段分隔符必须是 **Tab**。选成逗号会导致整份错位。

**想确认某段到底解析了没有**
段落右上角显示 **✓ 已对齐** 表示该段全部句子已有译文。

## 11. 开发者备忘

```bash
cd src-tauri
cargo test                        # 全部测试
cargo test --lib vocab::          # 只跑生词本 / Anki 导出
cargo clippy --all-targets        # 应无告警
cargo fmt                         # 格式化
```

改动约定：

- 后端仅 Rust（`src-tauri/`）；前端无 npm 依赖、无构建链，改完刷新即可
- 前端渲染用户/模型产出的文本一律转义（`escapeHtml` 或 `textContent`），不要用 `innerHTML` 拼接
- 新的 Tauri command 要同时在 `lib.rs` 的 `generate_handler!` 注册；`tests/frontend_contract.rs` 会校验前端调用的每个 command 都已注册
- async command 里不要直接 `block_on`，一律走 `crate::run_blocking`（`tests/command_dispatch.rs` 会扫描源码拦截）
- 断句正则等常量模式用 `OnceLock` 编译一次，不要在按段落调用的路径里重复 `Regex::new`
- 重新生成平台图标集：`cargo tauri icon src-tauri/assets/icon_source.svg`
