# Ready Reader 架构说明

## 1. 总体形态

```
Tauri 2 App (Rust 外壳 + Rust 后端)
├─ src/                  纯静态前端，无框架、无打包器、无 npm 依赖
└─ src-tauri/            进程内 command 后端
   ├─ commands/          17 个 Tauri command
   ├─ rusqlite (bundled) SQLite 编译进二进制
   ├─ reqwest (rustls)   LLM API 调用，不经过 webview
   └─ splitter/llm/…     业务逻辑模块
```

Rust 侧以 Tauri command 形式在进程内提供全部后端能力，因此：

- **没有 Python、没有本地 HTTP 服务、不占端口、不需要额外进程**
- 前端不发起网络请求（LLM 调用全部在 Rust 侧完成），CSP 得以保持最小化
- `frontendDist` 直接指向 `src/`，前端零构建步骤，改完刷新即可
- 单工程跨平台：macOS（`.app`/`.dmg`）、Windows（`.msi`）、Linux（`.deb`/`.AppImage`）

> 与同工作区的 `humming`（哼唱识谱）是两种相反的形态：`humming` 完全没有 Rust 后端，
> 全部逻辑在 webview 内完成；本工程则把解析、存储、导出全部放在 Rust 侧。
> 两者的目录骨架一致，差异仅由技术选型造成。

## 2. 数据流

```
导入 .md / .markdown / .txt
     ↓
markdown.rs   清洗：剥离 ATX 标题、强调、链接、图片、代码围栏、引用块；保留空行分段
     ↓
splitter.rs   断句：缩写 / 引语 / 小数保护 → 段落 p{n} + 句子 p{n}_s{n} 编号
     ↓
llm.rs        结构化解析：严格 JSON（句法切片 / 语境词义 / 典故 / 基调）
     ↓
db.rs         两级缓存写 SQLite：段落整段解析 + 单句深度分析
     ↓
src/          双栏对照渲染 + 语法透视镜 + 预取下一段
     ↓
vocab.rs      生词本 / Anki TSV 导出
export.rs     双语对照 Markdown 导出（只读缓存，不触发模型调用）
```

未配置 API Key 时，`llm.rs` 走内置离线演示引擎（启发式句法切片 + 经典段落预置精译），
**输出结构与在线路径完全一致**，因此缓存、导出、跳过判定都不需要为离线模式写分支。

## 3. 模块职责

| 文件 | 职责 |
| --- | --- |
| `src/index.html` | 界面骨架 |
| `src/main.js` | 入口脚本与主控制器：工具栏、文件导入、主题、进度弹窗 |
| `src/api.js` | Tauri command 调用封装（`window.__TAURI__.core.invoke`） |
| `src/dual_reader.js` | 双栏对照阅读器，句级悬停/点击联动高亮 |
| `src/inspector.js` | 语法透视镜：句法成分、语境词义、典故 |
| `src/vocabulary.js` | 生词本与 Anki 导出 |
| `src/settings.js` | 模型与解析引擎设置 |
| `src-tauri/src/lib.rs` | `run()` + 17 个 command 的 `generate_handler!` 注册 + `run_blocking` |
| `src-tauri/src/db.rs` | SQLite 连接、schema、迁移、默认设置种子 |
| `src-tauri/src/splitter.rs` | 精准断句器（缩写 / 引语 / 小数保护） |
| `src-tauri/src/markdown.rs` | Markdown / TXT 清洗 |
| `src-tauri/src/llm.rs` | LLM 客户端 + 离线演示引擎 |
| `src-tauri/src/prompts.rs` | 提示词模板与 JSON schema |
| `src-tauri/src/batch.rs` | 全文翻译与解析的后台任务编排（3 并发 / 可中断 / 可续跑） |
| `src-tauri/src/export.rs` | 译文与解析的 Markdown 导出 |
| `src-tauri/src/glossary.rs` | 全书术语表 |
| `src-tauri/src/vocab.rs` | 生词本 + Anki TSV 导出 |
| `src-tauri/src/commands/*.rs` | documents / analysis / vocabulary / settings 四组 command |

模块间前端一律用相对路径 `import`，因此 `src/` 可以整体改名或迁移而不动 import 语句。

## 4. 关键技术决策

### 4.1 后端进程内，不开 HTTP 服务

Tauri command 在进程内通过 IPC 调用，不占端口、不需要额外进程、也不需要在打包时
处理端口冲突。迁移前的 FastAPI + `localhost:8000` 方案因此整体删除。

### 4.2 纯 Rust，去掉 Python

断句器、LLM 离线引擎、Anki 导出、提示词全部从 Python 逐条平移。附带收益：
不再需要 venv、不再需要用户装 Python，Windows / Linux 打包无需附带运行时。

### 4.3 输入仅支持 Markdown

用户明确裁掉 EPUB / PDF。`.md` / `.markdown` 为主，`.txt` 兼容；导入时校验非空与
UTF-8 编码，异常输入直接拒绝并提示，不写入任何数据。

### 4.4 断句用 `fancy-regex`，而不是手写扫描

断句正则含前视断言：

```
([.?!…]+["'”’)\]]*)\s+(?=["'“‘A-Z0-9—]|$)
```

Rust 的 `regex` crate 不支持 lookahead，`fancy-regex` 支持，且能与原 Python 正则
逐条对照验证 —— 迁移时选了改动面最小的一种。

### 4.5 Claude / MiniMax 走 Anthropic 原生消息格式

旧 Python 代码对 `claude` provider 也发 Bearer token + `/chat/completions`，
而 Anthropic 实际要求 `x-api-key` + `/v1/messages`，原实现会 404。
Rust 版为 Anthropic 系（Claude / MiniMax）单开分支，响应映射 `content[0].text`
后再交给同一条 JSON 解析管线。

### 4.6 不依赖系统库

`rusqlite` 用 `features = ["bundled"]`（SQLite 编译进二进制），
`reqwest` 用 `default-features = false` + `rustls-tls`（不引入 OpenSSL）。
跨平台打包因此不依赖目标机器预装 SQLite 或 OpenSSL。

### 4.7 `withGlobalTauri: true`

前端经 `src/api.js` 调 `window.__TAURI__.core.invoke`，
需要 Tauri 注入全局对象。（`humming` 不调任何 IPC，故取 `false`。）

### 4.8 无前端构建链，因此无产物副本

前端零 npm 依赖、零构建步骤，`frontendDist` 直接指向 `src/`。
`humming` 曾用 SHA-1 内容哈希维护一份 `src-tauri/www/` 副本，已移除 ——
双份源码必然漂移，同步脚本一失效就会把过期内容静默打进发布包。

### 4.9 async command 里不直接 `block_on`

Tauri 把 `async fn` command 体当作 tokio runtime 上的 task 执行，
在其中调用 `tauri::async_runtime::block_on` 会 panic（"Cannot start a runtime from
within a runtime"），task 在 resolve invoke promise 之前就死掉 —— 表现是**按钮永远转圈**。
所有同步重活（SQLite、正则、文件读写）一律走 `crate::run_blocking` 转到阻塞池线程。

## 5. 测试策略

| 层 | 位置 | 覆盖 |
| --- | --- | --- |
| 单元 | `src-tauri/src/*.rs` 内联 | 断句、Markdown 清洗、提示词、LLM 解析与端点解析、术语表、生词本与 Anki 导出、旧库迁移 |
| command 调度契约 | `src-tauri/tests/command_dispatch.rs` | 每个 command 的调度形态；扫描源码拦截 async command 里的 `block_on` |
| 前后端契约 | `src-tauri/tests/frontend_contract.rs` | 前端调用的每个 command 必须在 `generate_handler!` 中注册；toast 不得用 `innerHTML` 拼接 |
| 全链路冒烟 | `src-tauri/tests/smoke.rs` | mock 模式 `load_sample` → `get_document` → `analyze_paragraph` → `get_sentence_analysis` → `add_vocabulary` → `export_anki` |

两个契约测试都是**防静默失效**设计：command 未注册时前端 `invoke` 只会 reject，
界面表现是按钮无反应、控制台无红字；目录结构若被改动，`frontend_contract.rs` 会
在 `cargo test` 时立刻失败而不是悄悄放过。`cargo test` 在提交前应全绿。
