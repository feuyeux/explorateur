# 国际象棋十二子 · 十二种语言

> 系列：**12 支短视频**，每支讲国际象棋的一颗棋子（6 类 × 黑白两方），每支用 **12 种语言**念出这颗棋子的名字。
> 产线：`explorateur/usine`（feuille）的 `karaoke-video` 线（词级高亮 + 状态帧 + 帧精确合片），**不消耗视频生成额度**。
> 账号：小红书 `lapin`（feuyeux）／抖音 `LapinAvecCulture`。

---

## 0. 一句话结论

**十二种语言，没有一种语言用马、象、车来指它们——棋子改了走法，名字还留在中世纪。**

这是整个系列的题眼，也是每支的脊柱：象在俄语里是 `слон`（大象）、在阿语里是 `فيل`（大象）、在印地语里是 `ऊँट`（骆驼）、在英语里是 `bishop`（主教）；马在英语里是 `knight`（骑士）而不是马；车在英语里是 `rook`（城堡）、在德语里是 `Turm`（塔）、在俄语里是 `ладья`（划桨的大船）。

观众看完带走的是这个发现，不是「12 语种 / 83 秒 / 逐词高亮」这种规格单。

## 1. 12 支分集表

| 话 | 标题 | 棋子 | 走法 | 价值 | 本支的战术要点 |
|---|---|---|---|---|---|
| 01 | 白后 | queen | 横直斜，任意格 | 9 | 后不要早出：早出的后会被车抽、被马跳进中心 |
| 02 | 黑后 | queen | 横直斜，任意格 | 9 | 后是最后一个该动的子：支点一立再动，用交换拿先手 |
| 03 | 白王 | king | 横直斜，只走一格 | 不可估值 | 尽早短易位，把中路让给马和后 |
| 04 | 黑王 | king | 横直斜，只走一格 | 不可估值 | 被车开线盯上才动；被将军先挡后跑 |
| 05 | 白象 | bishop | 只走斜线 | 3 | 一个管深格一个管浅格；别急着出，等兵让路 |
| 06 | 黑象 | bishop | 只走斜线 | 3 | 斜线被堵就只剩三分；残局常留象不留车 |
| 07 | 白马 | knight | 走日字 | 3 | 先挪开挡路的兵，再把马跳进中心 |
| 08 | 黑马 | knight | 走日字 | 3 | 后手先跳马进中心；兵堵死时马比象有用 |
| 09 | 白车 | rook | 横直，任意格 | 5 | 抢开放线：边线一路冲上去赶王出王翼 |
| 10 | 黑车 | rook | 横直，任意格 | 5 | 抢半开放线顶住白方后；支点没立不冲边线 |

## 2. 12 语种术语表（词典级事实，外部对照）

来源：Wikipedia《Chess piece》词条 *Overview of chess piece names* 表；另用 he.wikipedia《שחמט》与 el.wikipedia《Σκάκι》交叉核对希伯来语与希腊语。

| 棋子 | zh-CN | en-US | de-DE | fr-FR | es-ES | ru-RU | el-GR | hi-IN | ar-SA | he-IL | ja-JP | ko-KR |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 王 | 王 wáng | king | König | roi | rey | король | βασιλιάς | राजा | ملك | מלך | キング | 킹 |
| 后 | 皇后 huáng hòu | queen | Dame | dame | dama | ферзь | βασιλίσσα | रानी | ملكة | מלכה | クイーン | 퀸 |
| 车 | 车 jū | rook | Turm | tour | torre | ладья | ρολόι | हाथी | رخ | צריח | ルーク | 룩 |
| 象 | 象 xiàng | bishop | Läufer | fou | alfil | слон | σκακιέρα | ऊँट | فيل | רץ | ビショップ | 비숍 |
| 马 | 马 mǎ | knight | Springer | cavalier | caballo | конь | ίππος | घोड़ा | حصان | פרש | ナイト | 나이트 |
| 兵 | 兵 bīng | pawn | Bauer | pion | peón | пешка | πιόνι | प्यादा | جندي | רגלי | ポーン | 폰 |

异体与口径（写进发布词时只用主词，异体留在设计层）：

- 希腊语：主教有 `σκακιέρα` 与 `αξιωματικός`（军官）两说；兵 `πιόνι`（el.wikipedia「Παρτίδα πιονιού της βασίλισσας」= 后兵弃权弃兵，证明 πιόνι = 兵），亦作 `πεσσός`。
- 希伯来语：车 `צריח`（塔）与兵 `רגלי`（步兵）是 he.wikipedia《שחמט》用词；现代口语另有 `צורק`、`חייל`。
- 阿拉伯语：主教 `فيل`（大象）是古典阿语棋名；现代另见 `أسقف`（主教）。兵取 `جندي`（士兵），古典作 `بيدق`。
- 印地语：`हाथी`（大象）= 车、`ऊँट`（骆驼）= 象、`घोड़ा`（马）= 马、`प्यादा`（步兵）= 兵。
- 西班牙语 `alfil` 来自阿语 `al-fil`（大象）。
- 日语/韩语：片假名/外来语借词（`クイーン`/`퀸` 等），直接借自英语。

**事实分级**：以上为词典级可断言；「兵走两格 / 吃过路兵 / 升变 / 易位」属规则级，措辞用「通常 / 一般 / 最常见」限定，不写成绝对规则。

## 4. 事实源与目录

```

  data/series.json          ← 唯一事实源：系列信息 / 12 语种 / 6 类棋子 / 12 支旁白与战术
  data/copy.json            ← 发布词手写源（题眼文本 + 置顶话术）
  tools/gen-episodes.mjs    ← 生成器：scene HTML / voices.json / video.json / 封面源 / fonts.json
  tools/gen-copy.mjs        ← 发布词生成器：三平台 md + facts.json
  tools/build-all.mjs       ← 批产驱动：封面 → TTS → 合片 → 验收
  tools/check-fonts.mjs     ← 字体覆盖度门（实际拿到的字体 ⊇ 要渲染的字）
  tools/shot.mts            ← 抽帧（人眼看帧用：门禁全绿 ≠ 画面正确）
  fonts.json / fonts.css    ← 7 族字体子集（Google Fonts css2 逐字符子集，base64 内嵌）
  episodes/<id>/            ← 每支的工程与产物
    video_src.html  voices.json  video.json
    cover_pt_src.html  cover_t34_src.html  cover_lc_src.html
    tts/*.mp3|json  frames/ frames_v/  out/*.mp4
    cover_*.png  publish/{xiaohongshu,douyin,bilibili}.md  facts.json
    qa/*.png               ← 人工看过的帧（证据）
  qa_shot/*.png             ← 抽帧工具的临时产物（跨支对比用，不入库）
```

**唯一事实源**：`data/series.json`。走法落点、字体字符清单、词卡内容、发布词标题字数，全部由它派生——同一事实只存一处。

**字体字符清单也是派生的**：不是人肉分族，而是**从生成好的 HTML 反推**（与 `audit-charset` 同一套栈式归属算法，见 §6.4）。「哪个族渲染哪个字」因此在 HTML 与子集清单之间不会失步。

## 6. 环境坑与产线坑（本机实测，全踩过）

### 环境

1. **Edge headless 从 Node 子进程启动不落盘截图**——PowerShell 直接起 Edge 正常，Node `spawn` 起的 Edge 退出码 0 却写不出 PNG（相对路径/绝对路径都试过，加 `--user-data-dir` 也一样）。Chrome 两种都正常。→ 批产脚本固定 `FEUILLE_BROWSER=chrome`（工厂自带的覆盖口，见 `packages/core/src/platform.ts` 的 `FEUILLE_BROWSER`）。
2. **浏览器的 `--screenshot` 只认绝对路径**——传相对路径时进程退出 0、文件不产出，报错落在下游 sharp（`Input file is missing: xxx.png`），像是「文件丢了」。→ 所有截图输出路径先 `resolve`。
3. **edge-tts 的词边界不覆盖标点**——`karaoke` 线的 token 映射按字符位对齐，TTS 文本里带标点会让边界与 token 流错位（末尾 token 拿不到边界 → `tokenTimings` 抛错 / 高亮整体漂移）。→ TTS 文本去标点、用空格断句，**标点只留在画面上**；这样词边界与 token 流逐字对齐，高亮零漂移。

### 产线

4. **字体族归属靠人肉分族必然失步（本次返工的最大一处）**——第一版把「12 语种原生写法 + 人名」一律塞进西文族，页面里却用 `f-jp` / `f-ar` / `f-he` 渲染它们：`audit-charset` 报出 22 个缺字（日/本/語、عمر、נועה、रानी…）。根因不是漏抓字，而是**「哪个族渲染哪个字」这份映射有两个事实源**（HTML 的 class 与手写的 fonts.json）。→ 改成**从生成的 HTML 反推**：`deriveCharSets()` 用与 `audit-charset` 同一套栈式归属算法算出每族实际渲染的字符，fonts.json 由它派生；混排文字（「阿语 ملكة = 王后」）由 `spans()` 按 Unicode 脚本切成带族类的片段，不再靠人分族。门禁因此天然自洽：改稿后忘了重抓字体，`audit-charset` 立刻报缺字。
5. **`audit-charset` 只验「我们请求了什么」，不验「实际拿到了什么」**——Google 返回的子集里可能没有某些字（字体本身不含该码位），此时请求里有、渲染里没有 → 画面上是豆腐块，而子集门全绿。→ 自建 `tools/check-fonts.mjs`：解析 fonts.css 每个 `@font-face` 的 `unicode-range`，验每族实际覆盖 ⊇ 该族要渲染的字。（实测本次 7 族全部命中，缺口 0。）
6. **Chrome `--screenshot` 的输出目录必须先存在**——目录不存在时进程退出 0、**不产出文件、也不报错**（与坑 2 的表现一样，但成因不同：绝对路径也照样静默）。→ 抽帧前先建目录。
7. **截图的窗口尺寸必须等于画幅**——场景页是 1920×1080 / 1080×1920 的定尺页面，用 1080×1920 的窗口去截横版，只会拿到左上角一块（当时误判成「横版版式塌了」，其实是工具的窗口尺寸写死）。→ 抽帧工具按 fmt 选 window-size。
8. **机检的读者面只扫「标题+正文」，备选文案段是盲区**——`data/copy.json` 只有 ep01 写了抖音的 `alt`（投流版备选文案），拼装时把字面量 `undefined` 写进了另外 11 支的成稿，而 8 项机检全绿（它压根不扫那一段）。→ `gen-copy.mjs` 加两道自检：必填字段缺失当场抛错、成稿里出现 `undefined/null/NaN` 当场抛错；发布词因此**缺字段不可能再流进成稿**。
9. **edge-tts 的中文语音只对中文/拉丁/希腊发词边界**（实测：`俄语叫 слон` 只回「俄语」「叫」两个边界，漏 4 字；`阿语 حصان` 只回「阿语」，漏 4 字；`希腊语 ίππος`、`德语叫 Läufer` 则是全覆盖的）。词边界少覆盖 → 工厂按字符位把边界映到 token 上时刻意左漂 → 末尾 token 拿不到边界 → `tokenTimings` 返回 null → 工厂的 `karaoke tts` 崩在 `fmt2(null)`（报错完全看不出是哪支哪一语种）。本项目实测：ep05（旁白里有 `слон`/`فيل`）与 ep07（`конь`/`ίππος`/`حصان`）直接崩，ep09（`צריח`）侥幸没崩但**时序是漂的**。→ 三道处置：① 旁白改用中文说法（「俄语和阿拉伯语里，它干脆直接叫大象」），外文词留给 12 张词卡逐字展示；② `gen-episodes.mjs` 加**事前**守卫，旁白里出现中文语音覆盖不了的文字就当场抛错；③ `build-all.mjs` 加**事后**门，TTS 之后逐 token 查 `start/end` 是否为 null，有缺口就报清楚并停下，不再往下合片。

> 坑 1–3 目前是**本项目侧**的规避（环境变量 + 绝对路径 + 文案层去标点），没有改 `usine/packages` 的库代码。`covers.make()` 在传入相对输出路径时不落盘，属于库层可复现的缺陷，建议走 RSI 通道在 `usine` 侧修（`resolve(outPng)` + 反向验证测试）。

## 7. 验收链（每支都跑）

| 层 | 判据 | 实现 | 结果 |
|---|---|---|---|
| 渲染前 | 字符子集门 | `feuille poster audit-charset`（48 个页面全过） | 见 §8 |
| 渲染前 | **字体覆盖度门** | `node tools/check-fonts.mjs`（实际拿到的字体 ⊇ 要渲染的字） | 见 §8 |
| 渲染前 | 文案机检 | `feuille copy check --facts`（12 支 × 3 平台 × 8 项） | 见 §8 |
| 渲染后 | 时长实测 | `ffprobe`（竖/横两版） | 见 §8 |
| 渲染后 | 白页扫描 | `feuille karaoke scan-blank` | 全绿 |
| 渲染后 | AV 同步 | `feuille karaoke verify-sync`（抓帧 vs 状态帧像素差，竖/横各一次） | 全绿 |
| 渲染后 | **人眼** | `node tools/qa-frames.mjs`——从**成片**抽帧存证到 `episodes/<id>/qa/`（片头 / 旁白 / 12 张词卡 / 片尾，共 15 帧） | 见 §8 |

> 门禁全绿只证明「我检查的那件事成立」。棋盘裁切、词卡过暗、字号失衡、棋盘行映射差一行、字体族归属失步，这五处都是**门禁全绿之后**靠人眼抓到的。

> **`cover check` 的外圈底色门不纳入本系列验收链**（沿用 `examples/a01` / `a02` 的惯例）：那道门要求封面外圈是平台契约色（`#000` / `#FFF` / `#FB7299`），而本系列是「纸色设计稿」封面（`#F6F1E6`），两者天然冲突。替代验收：**人眼看裁切安全**（12 语种词表有没有出框、标题有没有压边）+ 抽帧存证（`qa/intro.png` 就是片头那一帧的实拍）。

### 建议回流给工厂（`usine`）的三处库层改进（本轮没改库代码）

1. **`karaoke tts` 的报错不可读**：`tokenTimings` 返回 `start/end = null` 时，CLI 崩在 `fmt2(null)`，只抛一句 `Cannot read properties of null (reading 'toFixed')`——看不出是哪支、哪一语种、哪个字。→ 让 `fmt2` 对 null 输出 `null` 并在末尾汇总「哪几个 token 没时间」；更根本的是 `gen_tts` 应在写盘前就报出「词边界没覆盖全文」。
2. **`tokenTimings` 假设词边界覆盖全文**：edge-tts 的中文语音对西里尔/阿语/天城/希伯来**不发边界**（§6.9），于是边界按字符位映射到 token 上时整体左漂，末尾 token 拿不到边界。→ 要么在 `tokenTimings` 里按「边界文本」而非「位置」对齐，要么让 `gen_tts` 在检测到覆盖缺口时报错而不是产出 null。
3. **`covers.make()` 传相对输出路径不落盘**（沿用本轮之前的发现）：建议 `resolve(outPng)` + 一条反向验证测试（相对路径调用后断言文件存在）。

> 这三处都属库层可复现缺陷，按 `usine/AGENTS.md` 的纪律应走 RSI 通道在工厂侧修，本轮全部在项目侧规避（`tools/` 与 `data/`），没有动 `usine/packages` 的代码。
