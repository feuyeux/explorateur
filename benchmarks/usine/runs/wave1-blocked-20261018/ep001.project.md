项目：给 languages/ 语种目录补上它自己写明缺的那道机检门（数据层 + 校验器强化）。

完整项目根：/home/user/evolution_project（仓库已在此，含 packages/ languages/ personas/ lessons/ skills/ docs/）。
所有持久交付物必须留在该项目根内；不要写到根外，也不要改 node_modules/ 或 dist/。

背景事实（都可在仓库里核实）：languages/README.md 的「门禁」一节**承认**语言目录当前没有专属机检
（原文：原 run.ps1 langs / scripts/verify_languages.py 门禁在重构时没有搬过来，当前语言目录没有专属机检）。
这意味着加一个新语种时，locale/label/flag/dir/fontCss/displayFontCss 这六项契约只靠人眼。
你要把这道门补上，并且遵守仓库自己的验证纪律（AGENTS.md 纪律 1/2/12：好数据放行是第一条断言；
加了新检查就要做反向验证；SKIP 不是 PASS）。

交付物（全部离线，不碰网络、不碰浏览器、不碰任何平台发布）:

1. 在 @feuille/core 里实现一个**纯函数**校验器 validateLanguageManifest（建议放 packages/core/src/data.ts，
   或新建 packages/core/src/languages.ts 并从 packages/core/src/index.ts 以 `export * as languages from './languages.js'`
   暂不要这样做——见第 5 条的归属约束；推荐直接在 data.ts 内实现并导出，或放一个新模块并同步更新 ownership.json）。
   口径必须与 languages/README.md 的字段表逐条对上：
   - locale 必须等于目录名；
   - label 非空；
   - flag 必须是**由 locale 的 ISO 区码推导出的那一对**区域指示符（U+1F1E6–U+1F1FF；README「为什么国旗必须等于 ISO 区码」一节），
     不是「flag 字段存在」——错旗必须被抓；
   - dir ∈ {ltr, rtl}；
   - fontCss 必须以通用族 sans-serif 兜底（末尾 token）；
   - displayFontCss 可选；给了则其末尾必须**整段接回**原 fontCss，且接回段之后不得再追加 serif（README 字段表原文）；
   - 返回问题列表（空 = 通过），纯函数、不抛异常，风格对齐 scene_schema.validateScene / persona.validatePersona。
2. 新增一个 CLI 叶子路由 `languages/validate`（packages/cli/src/leaves/languages-validate.ts + packages/cli/src/commands.ts 路由行），
   行为口径与 scene validate 一致：全目录逐个体检，有问题逐条打印并退出码 1，全过打印 PASS 行并退出码 0；
   支持 `--languages DIR`（缺省 = 仓库根 languages/）。usage 错误（如未知旗标）→ 退出码 2。

   b. **反向验证**：把 fixtures/langs/broken.json（在你自己的工作树里对应路径 <repo>/fixtures/langs/broken.json，
      由 wave 舞台预置）里的十种定向破坏**逐个**在临时目录里还原成 languages/<dirname>/manifest.json，
      断言每个都 FAIL 且报错命中该 case 的 expected 关键词；临时目录用例必须自己建、自己清；
   c. **接缝测试**：data.languageManifests(...) / fontsCss / flags / langLabel 在一个**只含坏 manifest** 的目录上
      不崩（抛 FeuilleError 或返回空/报错均可，但不得静默返回坏数据当好消息）。
4. 更新 languages/README.md 的「门禁」一节：把「没有专属机检」的**现状描述**改为指向新门禁

   README 的既有事实断言不得删除或弱化。
