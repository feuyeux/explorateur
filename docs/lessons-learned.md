## 1. 一条主线：两平台的流量机制决定形态分工

这是整个项目的组织原则，其余决策基本都由它派生。

| | 小红书 | 抖音 |
|---|---|---|
| 入口 | 搜索 + 话题页 + 合集 + 主页 | 纯推荐信息流 |
| 生命周期 | **长尾**，单条能持续被搜到 | **无长尾**，前 2 小时定生死，24 小时定型 |
| 决定指标 | 涨粉数、封面点击率 | 账号级**平均播放时长**（单条完播率在低播放量下是噪声，见 metrics-playbook §2.3） |
| 形态 | dialogue：一门课 5 语种各一支，可截图的对照表，进合集 | polyglot：三人同台，一支一个爆点 |

**推论**：同一批内容要按两套逻辑做，不能一份通吃。dialogue 的价值是「可截图、可对照、可收藏」，
这在小红书成立、在抖音不成立；polyglot 的价值是「一个人讲不完的梗交给三个人」，
这在抖音成立、在小红书不成立。合集在小红书是强信号，在抖音权重很低。

**实测验证（2026-10-06，发布后 8.5 小时）**：同一批片子，小红书涨 35 粉、观看 3,965、
曝光环比 +4249%；抖音涨 3 粉、平均播放时长 4.72s、完播率 0.8%（低于 99% 同类作者）。

**抖音那批全灭的归因，已被后续数据推翻两次**：
- 曾归因「8 分钟连发 10 条 + 凌晨 1 点发」——**错**。colors 课曾在 9 分钟内发 5 支，
  拿到 61 / 253 / 331 / 49 / 147 播放。批量发布本身不是主因。
- 曾归因「45–56 秒课程体量太长」——**也错**。colors 的 `durationBudget` 是
  `[40, 55]` 秒，跑量前四名（阿 331 / 俄 270 / 粤 259 / 印 253）**全在这个区间内**，
  与第二批同一时长。时长不是区分变量。

**唯一能解释全灭的，是语种与包装**——见 [strategy-2026q4.md](strategy-2026q4.md)：
抖音 colors 14 语种里 8 个播放 <50，且跑量的全是「有需求 + 供给稀缺」的蓝海语种。

**给抖音做内容的两条修正**（已收窄，取代原三条）：
1. 标题按「系列名 + 编号 + 语种 + 具体场景」写，话题用固定 5 个语种专属 tag
   ——colors 靠这个跑通，第二批的孤立知识点 + 临时凑话题全灭。
2. 一次只发 1–2 条，看完数据再决定要不要继续；发布时间放晚 7–11 点（这条仍属未验证的常识）。

## 2. 语种 TTS 语速差异 → 预算是放宽不是压台词

**现象**：edge-tts 各语种语速不同，**韩语比中文慢 5%–29%**（日语、英语次之）。
同一套行数，在中文里刚好的时长，换个语种就顶穿 §0 的 `durationBudget`。

**根因**：预算带是按中文定的，而渲染器在 TTS 阶段硬卡时长，超了直接不出片
（`src/usine/scene_video.py:412`）——**不改文本就出不来片**。

**处方**：
- **放宽 `durationBudget`，不要压台词。** 中文版每门都落在原上限的 77–98%，
  说明脚本长度本身没问题，问题在语种语速。
- 新值 = 该课各语种实测 min/max **± 2s 后取整到 5**。
- **声线一个都不动**（不变量：音色是人物身份的一部分，调预算不动声线）。
- 7 门受影响（social6 / intro6 / weekdays / body6 / zodiac6 / measure6 / gift-poison），
  逐门原值→新值与实测区间见 scene.json 的 `durationBudget` 字段（唯一事实源，不在文档里重复维护）。

## 3. 写作纪律（六条，不可协商）

1. **⚑ 注记先行**——所有语言学断言只允许出现在 ⚑ 注记里，正文与对照表不编造断言。
2. **独立创作、禁止互译**——五个语种各自自有的场景、意象、笑点。
   判据是**回译检查**：任一行译回中文不得逐词对上中文版那一行。
   骨架（17 行同节拍）可以共享，**内容不许共享**。
3. **事实分级**——词典级可断言；口语级的写「口语里」；假说级一律带「据说」。
   不确定的**宁可不写**。
4. **⚑ 注记要自然带出长尾搜索词**（如「XX语 + 场景词」）——小红书的 OCR/ASR 会读画面文字。
5. **敏感避让**——不出现品牌名、不劝酒、不涉酒精。
6. **不在 scene.md 里编造平台数据**——CES 分值、完播率、曝光倍数一律不写。

机器可渲的完整契约（节写法、引号对、注音、手势、⚑ 注记、问号、RTL、装置注册表）
在 [_格式契约.md](../thingking/final/_格式契约.md)，与 `parse_scene.py` / `qa_scene.py`
的真实判据逐条对齐，**以代码为准**。

## 4. 文案体例：两平台两套写法

| | 小红书 | 抖音 |
|---|---|---|
| 标题 | ≤20 字，短钩子 + emoji | ≤30 字，长句陈述 |
| 正文 | ≤1000 字，末尾话题并入正文末行（留尾随空格） | ≤1000 字，结尾真提问引导评论 |
| 结构 | 钩子开场 → `·` 分条 → 真提问 | 同左，但抖音应更前置更短 |
| 合集 | 每门课第 01 支「创建并加入」，其余点已有合集 | 权重低，不必投入 |
| 事实源 | `lessons/<课>/scene.md` 的 ⚑ 注记行号 | 同左 |

**事实不能改**：`lessons/_batch2/publish/*.md` 的每条断言都能回指 scene.md 的 ⚑ 行号；
转述可以更口语，找不到 ⚑ 出处的断言一律删掉，不自己补。

## 5. 发布与验收的通用判据

- **发布成功 ≠ 跳转成功**。权威判据只有一个：**回列表核验到这条作品**。
  抖音看「作品 (N)」计数递增**并刷新一次**（计数会滞后一跳）；
  小红书在笔记管理列表按标题搜到。
- ⛔ **草稿箱计数不是发布判据**（2026-10-06 证伪，坑 ⑭）。
  小红书在编辑过程中就自动存草稿，**发布成功后草稿不会被清理**——
  numbers 批次四支全部发布成功，草稿箱仍从 `(1)` 涨到 `(4)`。
  照旧记载的「计数增加 = 没发出去」去判，会把**成功报成失败**并触发重发。
- **批量核验用搜索框，不要滚列表**——两平台列表的滚动容器都不响应滚轮 action。
- **合集旁证分平台**：抖音能在合集详情页看「总集数」；小红书**没有合集管理页**，
  只能靠列表按标题核验。
- **每一步都要自带判据**。见 publish-playbook 元规则一：被执行的是流程步骤，
  不是坑列表，步骤本身写错时坑列表救不了。
- 逐条操作序列、31 条坑与三个取数坑，见专题手册。
